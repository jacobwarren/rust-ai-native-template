What changed in the mental model?

“An error means nothing happened” becomes “the error classification tells us which boundary was reached.” This is why a future save UI should retain the distinction already present in the driver.

Before replacement

Staging work can fail without replacing the old committed file. A retry follows correction of the underlying I/O problem.

After replacement

The new file can be visible while durable directory persistence is unconfirmed. Inspect/reopen before retry; do not promise the old state survived.

Questions a reviewer should ask

Does this guarantee survival of every crash?

No. The implementation uses file and directory sync but reports uncertainty when the latter fails. This walkthrough cannot certify hardware or filesystem durability. Read the storage contract.

Why not load the newest temporary file?

Staging files are uncommitted. Store::load reads the committed board.json and validates its envelope before replay. Inspect the semantic map.

Does a matching checksum prove who wrote the data?

No. The digest is unkeyed corruption detection, not authentication. Review the trust-boundary finding.
