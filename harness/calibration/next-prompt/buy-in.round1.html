02 The pitch

Every task page goes to a fresh subagent, and until now next only said which one to start. The orchestrator looked up the page's prompt in docs/ARTIFACTS.md, filled four braces, found the exemplar and carried the reviewer's findings to the rewrite by hand. Past tasks filled {task} three different ways, and the 24 review notes in two earlier logs were 100–276-character digests, never the reviewer's numbered findings (blindspot pass, items 01 and 07). Now author, review, rewrite and build steps carry one handover text to pass on unchanged, filled from five optional values in the task record, and verdict --notes - reads the reviewer's whole reply from stdin so a rewrite gets it word for word. This task used it on itself: the implementation notes and this page were started from next's own text, and the notes' round-1 review went through stdin.

03 What reviewers will ask

Q1Does this gate or block anything?

No. The step JSON gains two fields, handover and unfilled. Advisories, exit codes and the completion check are unchanged, and completion does not read the review log. The only gap near this work, artifact-gate-holes, is recorded as unaffected.

router.rs:351 calls handover::attach once, after the step is chosen · harness/tasks/next-prompt.json related_gaps
Q2What happens for the six tasks that have no prompt values?

The brace stays in the text, the missing record field is listed, the say tells you where to set it, and the exit code stays 0. A stub placeholder such as <Problem, one sentence> counts as missing. Captured with task_noun removed:

"handover": "… The prompt it answers: Keep implementation notes as you build {task}. …"
"unfilled": ["task_noun"]                                         exit 0
handover.rs:103 given(), :247 · test missing_values_stay_as_braces
Q3Can the prompts drift from the guide?

No, because there is only one copy. docs/ARTIFACTS.md is compiled into xtask, and the prompt table gained a File column, so rows are matched by file name, not by position. A test asserts the eight files are in page order, every brace is one next fills, every exemplar exists, and only the blindspot prompt opens "I'm about to {task}". The cost: renaming the guide stops xtask from building, and editing its table changes what next prints, though the guide is not a protected path.

handover.rs:14, :32 rows(), :262 next_prompts_match_the_artifacts_guide · transitions.rs PROTECTED_FILES
Q4Is the record change backward compatible?

New xtask reads old records unchanged, but not the other way round. The schema stays at 6 and prompt is optional, following the precedent set by tier. An xtask built from main refuses a record that has it:

$ (origin/main xtask) task-artifact next --task next-prompt
{"error":"unknown field `prompt`, expected one of `schema_version`, …","ok":false}   exit 1
task_record.rs:47–60 · only harness/tasks/next-prompt.json carries the object
Q5What stops someone piping a summary instead of the reply?

Nothing yet. The review say asks for "its whole reply", and the review hand-over asks the reviewer to end with FINDINGS: N. Nothing checks that the piped text is the full reply. Using that line as a check is open Decision B.

05 Risk, rollback, and what I need from you

Risk & rollback

  • Rollback is a revert. No other record uses prompt. To read this task with an older xtask, drop its prompt object.
  • The guide is now part of the binary. See Q3. The match test catches a reordered or renamed row, but not a reworded prompt.
  • Fixed before review: the missing-values note. On a review step it used to run on after the command to copy. It now comes first, so the say still ends with --notes -, and missing_values_stay_as_braces checks both ends (handover.rs:247). With task_noun unset:
    before… --findings N --notes - First fill its braces for task_noun: set them under prompt in harness/tasks/next-prompt.json and run next again, or replace them in the handover by hand.
    afterFirst fill the handover's braces for task_noun: set them under prompt in harness/tasks/next-prompt.json and run next again, or replace them by hand. Then: Start a fresh artifact-reviewer … --findings N --notes -
  • Size budget: router.rs is at 377 of the 400 lines allowed per file. The next change to it will need to move code out first.

What I need from you

A · Where the reviewer's reply format lives

The review hand-over asks for FINDINGS: N, but review-artifact's skill still says a PASS is one sentence.

B · Refuse a reply without the line?

It would catch a hand-written digest, but not one that copies the last line. So far one real reply has gone through, and it ended with the line.

Ship it?
