U2A unit variant would quietly accept {"command":"clear_done","ids":[1]}

Captured scratch test, clean copy, locked serde

A caller who meant to clear only some tasks would lose every done task. Use ClearDone {} and add this payload to the strict test.

U3The discovery test cannot run a clear_done example, and the obvious fix breaks complete

Every descriptor example must succeed on a seed that has one open task (tests/protocol.rs:13-21).

Captured today's four examples on three seeds, one line per seed

1 done           add Ok · complete Err("invalid_task") · remove Ok · undo Ok
1 open, 2 done   add Ok · complete Ok                  · remove Ok · undo Ok

Seed task 1 open and task 2 done, so the clear_done example removes [2].

U4One-step undo, ids that are never reused and ascending order are already built in

Undo restores a full copy of the board, next_id included (lib.rs:73-86). remove never lowers next_id (board.rs:82-85), and tasks live in a BTreeMap (board.rs:42). clear_done is one retain that collects the ids it drops, with no inverse and no sort.
