Landmine03

A new record field breaks every command, and a unit test, until the struct knows it

Task is #[serde(deny_unknown_fields)] (task_record.rs:27). Adding the field to this task's record first, in a clean copy:

$ cargo xtask task-artifact next --task next-prompt   (exit 1; coordination prints the same){"error":"unknown field `prompt_inputs`, expected one of `schema_version`, `id`, …, `summary`, `remaining` at line 31 column 17","ok":false}

stop_claim_pattern_matches_parsed_status also parses every file in harness/tasks/ as Task (task_record.rs:200, 215), so a record ahead of the struct fails cargo test too. tier is the precedent: optional, #[serde(default)], no schema bump. The schema is written down again in docs/COMPLETION.md (protected), examples/task-record.json and both write-ticket copies, which DOC007 keeps identical (checks.rs:189–207).

Why it bitesAn xtask built from main, say in another worktree, refuses this record once it carries the field: the one-way trade router-polish accepted for its review-log fields.
Add the record field as Option with serde(default) in the same commit as the first record that uses it, then update docs/COMPLETION.md, examples/task-record.json and both write-ticket copies. Run cargo xtask docs and the task_record tests before moving on.
Landmine04

Reading docs/ARTIFACTS.md at run time fails in the router tests, and its rows don't name the files

Router tests run the binary in a temp fixture repo holding four files and three harness JSON files (tests/support/mod.rs:44–51). There is no docs/, so a fs::read of the guide errors in every router test that reaches an author or review step (five of the eight). The repo already compiles files in (include_str!("artifact_foundation.css"), artifacts.rs:25; scripts in tests at transitions.rs:210 and task_record.rs:180), and cargo xtask is run -p xtask (.cargo/config.toml), so an edit to an included file rebuilds on the next run.

The table has two traps. Its Page column says "Brainstorm the intervention" or "Quiz me before I merge", not interventions.html or quiz.html; only row order matches DISCOVERY, NOTES, FINAL (artifacts.rs:14–22). And each exemplar is a link relative to docs/:

docs/ARTIFACTS.md:70, last cell[05](../examples/thariq/05-churn-brainstorm.html)
Why it bitesHanded over as written, the link points outside the repo root. Matched by display name, a reworded row silently drops a page's prompt.
Compile docs/ARTIFACTS.md in with include_str! and parse the prompt table into eight rows in artifacts.rs order; assert exactly eight rows, strip the quotes, and resolve exemplar links against docs/ to repo-relative paths.
Landmine05

Reporting a missing value as an advisory turns page steps into exit 3

Any non-empty advisories makes the process exit 3 (main.rs:30–34), and the fixture record has no brace values (support/mod.rs:99–105). The tests' helper:

xtask/tests/router.rs:22–24fn step(f: &Fixture) -> (String, String, u64) {
    let (code, v) = next(f);
    assert_eq!(code, 0, "{v}");
Why it bites"Warn when a brace can't be filled" is the natural design. It fails the four tests that call step() on a page step, and for any task without values it turns exit 3 from "a page was edited after review" into "always". A hard error is worse: next advises and never blocks (router.rs:1–3).
When a brace has no value, leave it in the prompt and list it in the step (e.g. "unfilled": ["area"]); keep advisories and the exit code as they are, and keep the existing router tests unchanged.

Landmine07

A rewrite's "findings" are a one-line note, and its kept version is the page itself

Row stores the findings as a count and notes as free text (router.rs:37–41). The 24 rows in workflow-router's and router-polish's logs carry notes of 100 to 276 characters, a digest of the reviewer's numbered findings, for example:

harness/task-artifacts/router-polish/reviews.json, plan.html round 1, reviseA1 error line/column from an older log (67 now, not 51); A1 example row invented without a label; 65% over exemplar height, A5 belongs in C, …

The rewrite step fires only while the page's hash equals the last revise row's (router.rs:255–258), so the kept copy is the page on disk byte for byte (cmp agreed in a clean copy), and it sits under git-ignored target/.

Why it bites"Carry the last review's notes and the kept version's path" gives a fresh author a summary written for the log plus a second copy of the file it is already rewriting. The full findings live only in the orchestrator's context; the kept path is useful only to the best step.
The rewrite step must hand the fresh author the reviewer's full numbered findings, not just the log's notes. Decide where they are stored before writing the step, and use the kept path only in the best step.
Convention08

The guide hands an author five things; the ticket's step carries three

ARTIFACTS.md gives the author the brief, the filled prompt, the exemplar, "the task context and the task's pages written so far" (lines 19–23), and the reviewer the page, prompt, exemplar and task context (44–47). The ticket names prompt, exemplar and output path. next already knows which pages exist (artifacts::exists, router.rs:329, 339); no file in the repo is "the task context". A cheaper model given only three fields skips the earlier pages, the drift the guide warns of: authors who "each derive the same headline finding again".

Each author and review step also lists the task's existing pages in table order and names harness/tasks/<id>.json, plus docs/plans/<id>.md when it exists, as the task context.
