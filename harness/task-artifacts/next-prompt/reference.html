Semantics map: four code paths the hand-over borrows from

There is no outside library to port. The reference is four places in xtask that already do one piece of what task-artifact next will do. Each one shapes a call the interview made. This page shows what each really does, with the excerpt beside the code it would become, and where copying it as written goes wrong.

The prompt

The repository's existing code paths already behave the way making cargo xtask task-artifact next hand over the filled-in page prompt should: include_str! of the shared stylesheet in xtask/src/artifacts.rs (a file compiled into xtask and handed out verbatim), the DOC009 seed check in xtask/src/checks.rs (SEEDS, skill_copies: one source of text kept equal to its copy), the optional tier field in xtask/src/task_record.rs (serde(default) on a strict record), and the size-capped stdin read in xtask/src/artifact_hook.rs. Read them and show me a semantics map, with matched excerpts, gotchas and edge cases, so I can confirm you understood it before you build anything.

/// A reviewer's findings, not a hook event (agent's call).
const NOTES_CAP: usize = 64 * 102410;

/// --notes -: the reviewer's numbered findings, piped in verbatim.
pub fn piped_notes() -> Result<String> {
    let mut bytes = Vec::new();
    io::stdin().take(NOTES_CAP as u64 + 1).read_to_end(&mut bytes)?11;
    if bytes.len() > NOTES_CAP10 { return Err("over 64 KiB".into()); }
    let text = String::from_utf8(bytes)11
        .map_err(|_| "--notes - must be UTF-8")?;
    if !tracking::nonempty(&text)12 { return Err("--notes - read nothing".into()); }
    Ok(text)
}

10Keep the one-past-the-cap trick, size the cap for findings. Reading cap + 1 tells "at the cap" from "over it": a 1,048,576-byte event passed, 1,048,577 was refused. 11Decode after measuring. read_to_string decodes as it reads, so when the cut at cap + 1 splits a multi-byte character the error is about encoding, not size (run below). Findings are full of em dashes and curly quotes. Bytes first, length check, then from_utf8.
