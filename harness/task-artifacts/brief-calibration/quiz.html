What was done: the mental model

Before, every check was a sample: the reviewer picked three claims, verified them by running things, and "uncited" was one way to fail the grounded question. Two of three baseline runs ran check ci on a draft, saw nine passes, and accepted a "9 / 9" tile that named no command. Now four checks come first and are judged from what the page gives a reader; the grounded question no longer mentions citation. They sit after rendering because the first wording, "before you run anything", made six of nine reviewers skip it.

Two behaviours a skim of the diff won't give you

01The test pins the whole check column; host drift is a different check's job

What
check_rows finds the line starting | Check |, skips the separator and takes the first cell of each row until the table ends. The reviewer test asserts that column equals CHECKS, in order, in both hosts. The author test reads its names from that table and requires - **name**: for each. Neither compares the hosts' wording; DOC007 in cargo xtask docs requires the copies to be byte-identical.
Why
A word search cannot stand in: with the cited row gone, "cited" is still in the brief, inside "uncited".

02The Fixed checks: line reports, it does not count

What
Every verdict carries one unnumbered line such as Fixed checks: consistent held; provenance failed (1); cited held; ticket n/a. A failed check points at its numbered finding. FINDINGS: N still counts only numbered findings, and that N goes into the verdict log.
Why
Held checks are not findings, and the hand-over's review line still asks for FINDINGS: N last. The verdict command parses the verdict and the count; the notes are free text. Nothing in xtask reads the new line; only the test checks that the brief asks for it.review-artifact SKILL.md:82–85 · xtask/src/handover.rs:204 · router.rs:119–126 · git grep -n "Fixed checks" HEAD -- xtask (one hit, briefs.rs:39)

What this leans on

The review hand-over. The ticket check reads the ticket, but the hand-over carries none of its text: it lists docs/plans/<id>.md among the task-context paths when that file exists, and leaves it out silently when it does not. Passing the acceptance text is held for a follow-up (buy-in call 4).
