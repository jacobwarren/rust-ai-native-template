Ten places to catch what the page reviewer misses, cheapest first

Where each of the four findings fresh reviewers raised only one to two times in three could be caught, located in the code with its cost. Check the ones that resonate. The bar at the bottom shows which findings your picks leave uncovered and which files they add beyond the ticket's scope.

The prompt
Here's the problem: In a calibration of 21 fresh reviews, every run caught pages that ran long or re-listed earlier pages, but a reply contradicting its page, reconstructed output shown as captured, an uncited claim and a dropped ticket requirement were caught only one to two times in three, and the author brief guards against none of them. Search the codebase and brainstorm the places we could intervene, from cheapest to most ambitious. I'll tell you which ones resonate.

Read: both page skills and agent definitions, handover.rs, the verdict path in router.rs, scripts/artifact-screenshots.cjs, docs/EVALUATION.md, next-prompt's review log and saved drafts. Ran: a prototype of #7 on the reference draft, and searches for the plan page's test names and the buy-in tiles' sources.

The pattern: in three of the four cases the evidence was on the page. The reference draft's contradicting reply line is drawn into the reply box when the page loads (reference.round1.html:459, by render() at :480), so no click was needed to see it. The plan page names all three of the ticket's tests and drops a clause inside one of them. The 9 / 9 tile sits on a page that never names check ci. Only reconstructed output cannot be told from captured output by looking (blindspots 03).

So the cheap options change what a reviewer must write down. The costly ones put evidence where looking is not enough. #3 and #4 are the ticket's own plan. The rest strengthen it or replace parts of it.

The ten

#1

Judge citation from the page alone, before confirming anything

S
.claude/skills/review-artifact/SKILL.md:17–22, :32

Found in code: the grounded row fails an "uncited" claim, but step 2 tells the reviewer to verify claims and run builds, so a reviewer who runs check ci has confirmed the tile (blindspots 02). Split the row in two: cited, judged from the page before any command runs, and true, sampled afterwards. The rule decides which committed pages pass. The committed buy-in page passed every fresh run with a 7 / 7 and a 93 / 93 tile that name no command beside them (buy-in.html:209–210). Only the 9 / 9 tile has the sentence naming cargo xtask check ci (:214).

CostTwo sentences, mirrored to .agents/. First settle what must carry a source (blindspots 01 and 02), or the rerun's committed-page baseline moves.
#2

Asking for quotes turns looking into a written step: the reviewer copies the default reply's lines next to the conclusions they summarize, the caption over each output block, the source beside each stat tile, and each ticket clause next to where the page meets it.

#3

Four fixed-check rows in the reviewer's question table

Sticket's plan
review-artifact SKILL.md:28–37, :59–60 · new xtask/tests/briefs.rs

Found in code: the table's eight questions cover learning, job, grounding, interactions, showing, length, focus and rendering. None asks whether the page agrees with itself, whether output was captured, or whether the ticket is met. This is reviewer_brief_runs_the_fixed_checks. Each row needs an n/a: a reply is owed only by the five discovery pages (:59–60), and the ticket check bears on plan and buy-in. A row alone may not be enough: the grounded row has named "uncited" all along (:32), and two of three runs still let the 9 / 9 tile through.

CostFour rows, mirrored; a test that matches each check's short name in both hosts. DOC007 keeps the copies equal.
#4

Matching rules in the author brief, so the page arrives clean

Sticket's plan
.claude/skills/author-artifact/SKILL.md:18–24, :31–32, :37–38

Found in code: the author brief asks for "a concrete basis the reader can follow" (:18–21) but not that it sit beside the claim. It asks for a reply (:31–32) but not that the reply be built from the data the page renders; the draft typed its reply separately from its table (blindspots 04). It forbids "verification boilerplate" (:37–38) without the one-line provenance label docs/ARTIFACTS.md:139–140 allows. It never mentions the ticket. This is author_brief_answers_each_fixed_check: four rules under the reviewer's check names.

CostFour sentences, mirrored. The only brief change that prevents a defect instead of catching it, so the reviewer's 1-in-3 matters less.
#5

Name the page's own checks in the review hand-over

S–Madds xtask
xtask/src/handover.rs:191–205 · xtask/tests/handover.rs:264–271

Found in code: the hand-over's last line is the only instruction on how to review that it carries ("Follow the review-artifact skill: PASS or REVISE … FINDINGS: N …", :203–205). The calibration showed how hard hand-over text steers. Four reviewers given a different prompt all failed the page on that ground (ticket, Calibration record). handover() already adds lines by page, such as the answering rule for interview and buy-in at :191–193. CostA match on the page name and one test line. xtask/ is protected (transitions.rs:40), so it rides on the receipt the .claude/ edit already needs. Outside the ticket's scope list.

#9

Make captured output come from a command the reviewer can rerun

Lnew command
new task-artifact capture in xtask/src/main.rs and artifacts.rs

Found in code: the markup cannot tell captured lines from typed ones; in the buy-in draft both are the same tuples in one array (blindspots 03). A cargo xtask task-artifact capture -- CMD that runs CMD in a clean copy and prints an escaped block, tagged in a data attribute with the command and commit, gives the reviewer something to rerun. Any untagged block is then reconstructed by definition. Tiles that count a run, such as 9 / 9 and 93 / 93, could cite the same tag.

CostA reviewer running commands a page names, pinning the commit (blindspots 05), and keeping the hash off the visible page (author brief :37–38). Most of the four checks still need judgement.
#10

A seeded-defect calibration set with known answers

Lmeasures
docs/EVALUATION.md:44–50 · target/artifact-reviews/next-prompt/ · .gitignore:1

Found in code: four natural cases, with baselines of 2/3, 2/3, 1/3 and 1/4, leave one step of headroom each (blindspots 01). The drafts live under the ignored /target/. EVALUATION.md asks a semantic checker for "benign near-misses, calibration" (:47). Commit the three drafts and three passing pages as fixtures. Add four seeded copies of passing pages, one defect each: a reply line flipped, a tile's source deleted, a caption changed to "captured", a ticket clause dropped. Each class then has a known answer, and the untouched originals are the near-misses.

CostWriting the defects, a new fixture folder, and three fresh reviews for each of the ten cases on every rerun, about 30 reviews. It catches nothing itself, so it targets none of the four; it tells you which of #1–#9 worked.
