1 What the question table does, and its author mirror

Each row is a question with an observable “Fails when” (review-artifact SKILL.md:28–37). The rows are answered last, in step 4, as “a short verdict with the place on the page” (:25–26), after the reviewer has rendered the page, verified at least three claims and used the controls. So they judge evidence the steps already gathered. Page types reach the table only through the job row, so no row is ever n/a. Findings are keyed by row (“each names the question it fails”, :65–66), and a PASS shows only the first answer (:64).

Seven of the eight rows have an author mirror. The closest mirror, with the same yardstick and the same verb, belongs to the length row, which every calibration run caught. The shaded lines have neither a row nor a rule. Figures count the fresh reviews that raised each defect (ticket, Calibration record).

3 Table semantics: preserved, changed, left out

Preserved

  • Name plus an observable “fails when”, never a virtue to weigh
  • A short verdict with the place on the page (:25–26)
  • Findings name what they fail (:65–66), now by check name
  • One failure is enough (:19–20)

Deliberately changed

  • Runs before claim sampling, from the page and the ticket alone (Q2)
  • An n/a column instead of routing through the job row (note 8)
  • Reported on a PASS on one unnumbered line (Q4); today a PASS shows one answer (:64)
  • The grounded row narrows to “wrong or vague”; cited takes “uncited” so the rule lives in one place

Left out

  • The three-claim sample as citation's scope: cited covers every tile, headline number and claim a choice rests on (blindspots 02)
  • Repair by confirmation: a true but unsourced tile still fails
  • Hand-over changes and an enforced rerun: the skills only (Q1, Q8)
