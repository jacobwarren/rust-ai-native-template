Missing concept04

The reviewer has Read, Grep, Glob, Bash and WebFetch (.claude/agents/artifact-reviewer.md:5). scripts/artifact-screenshots.cjs renders each page in its default state at two widths, and nothing in its 182 lines clicks or types. So "the reply matches the page" means reading JavaScript. In the reference draft the contradiction was a string hard-coded in reply(), typed separately from the table it summarizes:

Convention06

A passed check is not a finding, and the reviewer's count is set in xtask, not the skill

The review skill never mentions the closing FINDINGS: N line. handover.rs:204 appends it to every review handover ("counting every finding you listed"), tests/handover.rs:269 pins it, and ARTIFACTS.md:61–62 says "N counts every finding the reviewer listed, blocking or not." A brief that asks for a numbered result per fixed check inflates N in reviews.json, the log your rerun is compared against. The PASS form, "PASS with the one-sentence answer to the first question" (SKILL.md:64), gives no sign that the checks ran.

Why it bitesRerun counts can rise only because "held" lines got numbers. Not every check applies either: a reply is required only of discovery pages (SKILL.md:59–60), so each check needs an "n/a".
Convention07

The brief edits are protected product code, and a test that readiness does not list is never required

.claude/ and harness/readiness.json are protected (transitions.rs:39–60), so the change needs a policy receipt. Its digest covers every protected file, so write it after the last protected edit. .agents/ and docs/EVALUATION.md are not protected; only DOC007 (checks.rs:189–209) keeps the Codex copy equal. Neither skill folder is administrative (artifacts.rs:33–43), so the first brief edit counts as product code, and the five discovery pages must be committed before it. A named test counts only if it is listed under task-artifacts in readiness and prints test NAME ... ok in the CI log (readiness.rs:151–155).

Why it bitesIf briefs.rs lands without its readiness entries, completion never requires those two tests, and a later edit can delete both without any gate noticing.
