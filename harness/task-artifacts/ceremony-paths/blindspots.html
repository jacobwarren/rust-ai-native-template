The blindspots

Landmine01

A skill can register hooks for the rest of the session, which is why .claude/ is protected

Commit 7fa7665 ("Protect agent host config…", 2026-11-04) added .claude/ to PROTECTED_PREFIXES "so removing or weakening a hook needs a transition receipt." The repo already puts hooks in frontmatter (.claude/agents/artifact-author.md:8-14), and Claude Code accepts the same key in a skill: hooks are "registers[ed] when the skill is invoked and keeps running for the rest of the session"; allowed-tools run "without asking permission"; !`cmd` "runs shell commands before the skill content is sent."

Why it bitesExempt .claude/skills/investigate/ and a small task with no receipt can give it a PreToolUse or Stop hook. Its description asks to be loaded "when a task asks you to find, diagnose or fix behavior", so that hook runs in most sessions. docs/COMPLETION.md:198-199, "changing a hook on a branch needs a transition receipt", would quietly stop being true.

transitions.rs:39-47; code.claude.com/docs/en/skills (frontmatter table) and /docs/en/hooks ("Hooks in skills and agents"). Not checked: whether a skill hook can override the guard's ask.

Landmine03

The guard sees directories and moves, not just files

Handoff reads file paths from git, but the guard tiers whatever a command writes: rm, mv and cp operands as given (agent-hook.sh:210-224), resolved against the event's cwd (121-134), and decide keeps the first path of the highest rank (167, strict -gt). Missing concept04

The folder name becomes the protection key, so DOC008 becomes a policy check

Agents preload ceremony skills by name (skills: - author-artifact, artifact-author.md:6-7); the narrowed rule matches by folder. DOC008 is the only link, and it accepts any matching name: line (checks.rs:216-219, .any(…)).

captured: cargo xtask docs, new skills/helper/SKILL.md in both hosts

name: author-artifact                → DOC008 … must … set name: helper
name: helper + name: author-artifact → no DOC007/DOC008 error
Why it bitesToday that folder is protected anyway; after the change it is free. How each host reads a duplicate YAML key is not verified: one may refuse the file, another may keep the last value and load a second author-artifact. DOC008 is under xtask/, which this task already changes, so tightening it adds no new receipt.
Convention05

The Codex copies were never protected; DOC007 holds them in place

PROTECTED_PREFIXES has .claude/ and .codex/ but not .agents/ (transitions.rs:39-47). Only size::CEREMONY covers .agents/skills/, which is why the baseline lists only the Claude copy under protected_files. The guard's whole answer to an Edit of .agents/skills/author-artifact/SKILL.md is {} (captured: agent-hook.sh guard claude).

Why it bites"Ceremony skills in both hosts" is two mechanisms: either copy forces a standard task, but only the .claude copy needs a receipt or gets a note. That is safe only because DOC007 fails a branch where the copies differ. A guard test expecting a note for the .agents copy fails, and a doc line saying both are protected would be wrong.

Convention06

One list, three readers, and the parity test parses one shell line

script_list finds the line starting NAME=" in agent-hook.sh, strips the closing quote and splits on whitespace (transitions.rs:209-219); guard_tiers_match_protected_paths compares that to the Rust const (221-225). So the guard list must be one unindented line with the same strings in the same order. size.rs needs the same names for both hosts; its own literal would be a third copy with no test.

Why it bitesdocs/skills/ is not one file per skill: author-artifact.md and review-artifact.md are pointers, investigate.md is a seed, write-ticket has none (ls docs/skills). Those entries cannot be built from the skill list.
