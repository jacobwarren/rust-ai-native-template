02 The pitch

Today any skill edit is refused as a small task, because every path under .claude/ is protected and every skill folder counts as ceremony. A one-word fix costs eight pages, sixteen subagent runs and a policy receipt. This change keeps that cost for the three skills that define the ceremony and drops it for the rest. The workflow-router task dropped this carve-out because frontmatter can register hooks and only the receipt stood in the way. This branch adds the missing check: CI refuses any skill outside the ceremony that is more than plain Markdown (tab 2). The change is 15 files, +359 −17: code 4 files +122 −7, tests 3 files +121, docs and config 6 files +33 −10, the receipt +23 and the plan +60. No record or receipt format changes, so a revert restores today's rules.

04 What the demo does not answer

Q1When does an agent find out its skill edit broke the rule?
At the next cargo xtask docs, not at the edit. The guard never runs Cargo, so on this branch it says nothing when a hook is added to investigate (tab 2, «At the edit»). The fast and ci profiles both run docs, and completion refuses a ci report that is not ok, so the hook cannot ship, but the session that adds it gets no warning. A guard reminder on every free-skill edit is call 7 below.
scripts/agent-hook.sh:4; harness/config.json:59, 106; xtask/src/readiness.rs:113-116
Q2Do the guard and handoff always agree?
No. The guard is advisory and coarser in both directions; handoff reads git's file list and decides. The guard notes any one-segment path under .claude/skills/, so rm -r .claude/skills/investigate gets a receipt note handoff will not ask for (call 9). It stays silent for rm -r .claude and after a cd (risks below), as on main; handoff catches both.
