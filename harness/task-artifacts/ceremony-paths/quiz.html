1 · Why it changed

On main, transitions::protected matched every path under .claude/, and size::CEREMONY listed all of docs/skills/, .agents/skills/ and .claude/skills/. A one-line fix to the investigate skill therefore needed a receipt and eight pages. The blindspots and plan pages walk through that cost.

Only three skills define the task-page ceremony. The workflow-router task tried this carve-out and dropped it, because skill frontmatter can register hooks, grant tools and run shell commands at load, and the receipt was all that stopped it (harness/tasks/ceremony-paths.json discoveries[0]). So the change has two halves: narrow both path rules to a named list, and add checks that keep every other skill plain Markdown.

3 · What was done

excerpt · xtask/src/transitions.rs:66-88, verbatim

pub(crate) const CEREMONY_SKILLS: [&str; 3] =
    ["author-artifact", "review-artifact", "write-ticket"];

/// Whether `path` lies in one of the ceremony skills, in either host's folder.
/// Names compare without case: on a case-insensitive checkout
/// `Author-Artifact/` is the ceremony skill's own folder. A file loose in the
/// skills folder, outside any skill, counts as ceremony too.
pub(crate) fn ceremony_skill(path: &str) -> bool {
    [".claude/skills/", ".agents/skills/"].iter().any(|host| {
        path.strip_prefix(host)
            .is_some_and(|rest| match rest.split_once('/') {
                Some((name, _)) => CEREMONY_SKILLS.iter().any(|s| s.eq_ignore_ascii_case(name)),
                None => true,
            })
    })
}

pub(crate) fn protected(path: &str) -> bool {
    if path.starts_with(".claude/skills/") {
        return ceremony_skill(path);
    }
    PROTECTED_PREFIXES.iter().any(|p| path.starts_with(p)) || PROTECTED_FILES.contains(&path)
}
