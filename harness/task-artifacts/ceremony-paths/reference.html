Semantics map: administrative() and the narrowed ceremony paths

What the administrative-path exemption does, what a match means to each of its readers, and every place the narrowed rule cannot copy it. Flag anything I got wrong. Nothing gets built until you sign off.

The prompt
The administrative-path exemption in xtask/src/artifacts.rs already behaves the way the narrowed ceremony paths should. Read it and show me a semantics map, with matched excerpts, gotchas and edge cases, so I can confirm you understood it before you build anything.
Short answer: partly

administrative() is the right model for how to match a path (pair A). It is the wrong model for what a match does (§2): each of its readers exempts a path from more than a free skill should escape. The narrowed rule has to live in protected(), size::forces_standard and the default edit guard, and none of them calls administrative() (pair B).

1What administrative() actually does

  • It is a pure string test with six entries. Four folder prefixes end in /, and two exact file names follow. It uses starts_with and == and nothing else: no normalization, no case folding, no filesystem access. artifacts.rs:33-43; git log -L33,43:xtask/src/artifacts.rs lists one commit, ed782ef.
  • The receipt and the default guard never call it. transitions::required filters by protected() alone, and scripts/agent-hook.sh has no copy of the list. The administrative paths escape a receipt only because no protected entry covers them. transitions.rs:114-115; captured: grep -c administrative scripts/agent-hook.sh → 0.
  • An administrative path is still checked by other rules. Closing a gap in harness/gaps.json needs a receipt, and receipts under harness/transitions/ are append-only. A free skill will likewise stay under the DOC007–DOC010 skill lints. transitions.rs:65-113; checks.rs:205-235.

1A trailing slash is a folder boundary, and a miss fails safe. harness/tasks and harness/tasks-old/x.json are not administrative (probe, §5). The sketch gets the same boundary from split_once('/'): a path with no name segment followed by /, such as .claude/skills/README.md, stays protected. Git hands Rust files only, so bare folders reach just the guard (blindspot card 03).
2Exact files compare whole strings. harness/gaps.json.bak is not administrative (probe). The sketch leaves PROTECTED_FILES alone. .claude/settings.json stays protected through the .claude/ prefix and is never a skill.
3There is no normalization; the callers make it safe. docs/plans/../../xtask/src/main.rs is administrative (probe). That is harmless because callers pass git's repo-relative paths (history.rs:33-95) or the output of relative(), which refuses any .. or . component (artifacts.rs:45-58). The sketch inherits this, so a .. spelling of a ceremony skill is free in Rust (§5, last rows). The guard resolves .. in normalize() (agent-hook.sh:105-116) before tier() sees the path.
4The failure direction inverts. administrative() lists what is exempt, so a typo or a different case (Docs/Plans/x.md, probe) makes a path product code, which is stricter. The narrowed rule lists what stays protected, so any name missing from CEREMONY_SKILLS is free. That is the price of a new skill being small (interview, settled list). Interventions #5, the allowlist, keeps the reference's direction.

4Port, change, or leave behind

Port exactly
  • Prefix up to a slash, exact files apart. A bare or partial name never matches (notes 1, 2).
  • A pure string test on git's repo-relative paths. No folding or normalization in Rust (note 3).
  • One owner in Rust. One const that every Rust reader calls, under protected xtask/ (note 5).
  • Exempt from one rule, checked by the rest. Free skills still pass DOC007–DOC010.
Deliberately different
  • Subtracts from protected() instead of standing beside it (R5).
  • Exception inside the predicate, shared by two readers (note 5).
  • A shell copy with a parity test, folding case only where git does (notes 7, 8).
  • Lists what stays protected, so a missing name is free (note 4).
Leave behind
  • Skipping the line count (R1).
  • Tolerating uncommitted edits at completion (R2).
  • “Not a code commit” in the page order (R3).
  • Bypassing the opt-in page guard (R4).
