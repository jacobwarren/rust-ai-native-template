Where to intervene: ceremony paths

Nine places the cost of a skill edit is decided, from a one-line change to a new tier. Each one is shown against the same three edits so you can see what it frees and what it lets through. Tick the ones that resonate.

The prompt
Here's the problem: Every path under .claude/ is protected and every skill folder counts as ceremony, so fixing or adding a skill unrelated to the task pages, such as investigate, forces a standard task with eight pages and a policy receipt. Search the codebase and brainstorm the places we could intervene, from cheapest to most ambitious. I'll tell you which ones resonate.

The interventions

#1

List skill folders as administrative paths

S · 1 linetrap
xtask/src/artifacts.rs:33-43 · size.rs:90-96

Found in codecheck_small skips an administrative path before it asks forces_standard, so a listed folder drops out of both the ceremony check and the line count. It is the exemption the ticket names as its reference, so it is the first thing a reader reaches for.

But transitions::required filters by protected() alone (transitions.rs:114-115) and never asks administrative(), so the receipt stays. And committed() lets administrative paths sit uncommitted at completion (artifacts.rs:147-151), while order() does not count them as code (165-167).

CostsPages go, the receipt stays, a skill of any length counts zero lines, and completion accepts the skill edit uncommitted. It solves half the problem and opens two new holes.
#2

Keep the receipt, drop the pages

S · size.rs only
xtask/src/size.rs:11-29

Found in codeforces_standard opens with transitions::protected(path) (size.rs:23), so every receipt path is also an eight-page path. The two costs don't have to go together: a small task already “owes … any transition receipt” (docs/ARTIFACTS.md:107-108), and handoff checks receipts at every tier. Keep non-ceremony skill folders protected and stop them forcing standard. transitions.rs, the guard and its parity test stay unchanged, the guard's receipt note on investigate stays true, and so does COMPLETION.md:198-199: “changing a hook on a branch needs a transition receipt.”

#7

Protect a free skill's frontmatter, not the whole file

L
transitions.rs:103-130 · history.rs:102-123

Found in coderequired() builds the policy digest from history::before and current, which hash whole files. For a non-ceremony SKILL.md, hash only the block between the --- lines. Body edits then change no digest and need no receipt. Any frontmatter change, including a new skill or a key no lint knows yet, needs one, and size.rs drops these folders from forces_standard as in #2.

FreesText fixes become free. New skills and hooks become small tasks with a receipt. Unlike #6 it catches keys nobody has listed.
CostsThe policy digest stops meaning “these files”. The guard sees only a path, so it either notes every skill edit or parses old_string. !`cmd` lives in the body, so the injection half of #6 is still needed.
