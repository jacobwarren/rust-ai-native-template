TASK FIELDNOTES · discovery-workbench

Implementation notes

Resolve task uncertainty using five interactive artifacts and preserve explicit human feedback.

NOTE 01

Observation / changed assumption

The original scalar preflight fields could not represent human choices. Five typed tool models and a separate imported feedback history now exist. Browser proposals cannot silently write source.

Decision and rationale

Use task schema v4 and artifact schema v2 for active discovery. Preserve old preflight, discoveries and feedback; bind exports to task/discovery/feedback hashes and reject stale choices.

Effect on behavior and next steps

All five UIs passed a generated-DOM integration test, including real export → CLI import, duplicate import rejection, reopened decisions, interview edits, semantic highlights and alternate interface previews. Browser geometry and actual file-download permissions remain unverified by that test.

NOTE 02

Observation / changed assumption

DOM integration exercised all five generated tools and imported their actual exported JSON through the real CLI. Selected constraints and sourced answers now also assemble into the plan artifact. Publication status previously tracked only notes, which would misleadingly label a brief current after new discovery.

Decision and rationale

Bind visible publication state and completion to notes plus discovery and feedback hashes. Preserve archived schemas, require v4 for active admission, and label native browser qualification separately from DOM behavior checks.

Effect on behavior and next steps

Old open tabs cannot overwrite current decisions. Missing required pages, invalid content, stale feedback and changed publication inputs fail. No browser rendering or actual clipboard/download permission result is claimed.
