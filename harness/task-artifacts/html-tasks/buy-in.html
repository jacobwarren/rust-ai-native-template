TASK FIELDNOTES · html-tasks

The case for this change

Every active task has a durable HTML review page spanning unknowns, implementation notes, buy-in and an interactive quiz.

What changed and why

Generic unknowns prose is replaced by five mandatory interactive tools: blindspots, interventions, interview, reference semantics and tweakable plan. Task v4 and artifact v2 preserve existing histories while representing findings, questions and choices directly.

Demonstration / before and after

The generated-UI test selects constraints and interventions, enters and revisits a custom interview answer, highlights matched semantics, exports a correction, changes a plan preview and imports each actual export through the real CLI. Replaying an old export fails, and reopening the plan shows recorded decisions.

Verification and boundaries

Rust CLI regressions pass for required artifacts, malformed/stale feedback, wrong-task imports, publication invalidation, unanswered blocking questions and history preservation. The actual generated scripts pass DOM integration. Final source-bound CI/completion reports are separate under target/verification/discovery-workbench. Native layout and clipboard/download behavior still require human browser review.

Risks, tradeoffs and decisions needed

Feedback actors are declared, not authenticated. Browser drafts do not modify the repository until explicit import. Opening an old tab after another import requires refreshing; imports deliberately reject stale feedback rather than guessing how to merge it. The five requested discovery tools are implemented; optional domain explainers, mock builders and visual design explorations remain future work.

What changed and why

Risks, tradeoffs and decisions needed

Archived v1/v2 records remain readable; active tasks must migrate to v3. The fixed renderer supports text, links and quiz interaction, not arbitrary task-authored scripts or embedded applications.
