A1 · Data model: reviews.json beside the pages

// xtask/src/router.rs (new, 313 lines)
pub const LOG: &str = "reviews.json";
const REVIEWS: usize = 3;       // first draft + two rewrites

#[serde(rename_all = "snake_case")]
pub enum Verdict { Pass, Revise, Best }   ①

#[serde(deny_unknown_fields)]
pub struct Row {
    pub page: String,       // one of the eight
    pub round: usize,       ②
    pub verdict: Verdict,
    pub sha256: String,     // the file as reviewed
    pub reviewer: String,   // an id: letters, digits, - _
    pub notes: String,      // may be ""
}
#[serde(deny_unknown_fields)]
pub struct Log { pub schema_version: u32, pub rows: Vec<Row> }
// written pretty-printed to harness/task-artifacts/<task>/reviews.json
  • ·One file per task, committed with the page it judges. Its folder is administrative, so it never counts as product code.
  • ·Strict. A hand-typed "Pass" stops next with exit 1: reviews.json: unknown variant `Pass`, expected one of `pass`, `revise`, `best` at line 15 column 23.
  • ·The hash is of the working file when verdict runs. Whether a page is committed is asked of git status, because eol=lf makes a CRLF page hash differently from what git stores while status calls it clean.
Choice ①best as a third verdict

Plan's pick: a third value, best, allowed only after three revise rows and only on a version some row reviewed. It records which version "commit the best" kept, by taking that version's round. Refusals read best is for a page whose 3 reviews all asked for revision; interview.html has 0 and … differs from every reviewed version; restore the best one first.

Alternative: two verdicts only; the notes say a page ran out of rewrites. Simpler, but the log can't tell "passed" from "gave up", the rewrite-rate data the request asked for.

Choice ②round means the version reviewed

Plan's pick: round = number of revise rows so far + 1. 1 is the first draft, 2 the first rewrite, 3 the second; best takes the round of the version it keeps (router.rs:104-133). Consequence: pass a page, hand-edit it, review it again, and both rows say "round": 1, since no rewrite happened.

Alternative: round = this page's review count + 1, unique per row. No ties, but "round 3" no longer means "second rewrite", and the cap still has to count revise rows.

A2 · Two commands and what they print

cargo xtask task-artifact next --task ID
cargo xtask task-artifact verdict --task ID --page PAGE --verdict pass|revise|best --reviewer NAME --notes TEXT

Every verdict flag is required, in that order; --notes "" is allowed.

Choice ③Exit 3 for advice

Plan's pick: 0 for a plain step, 1 for an error, 3 when ok and advisories is non-empty (main.rs:29-39; cargo xtask passes the 3 through). Two advisories exist: … was edited after its Pass verdict (or Best), checked on every logged page, not only those before the next step; and reviews.json no longer starts with its committed rows; record verdicts only with task-artifact verdict. No script calls next, so no set -e trips on it.

Alternative: always exit 0; advice lives only in the JSON. Safe for any wrapper, but an agent that checks only the status misses the signal aimed at this task's drift: hand edits after a final review.

A3 · Tasks from before the log

With no reviews.json, a committed page counts as reviewed elsewhere (router.rs:187), so agent-workflow reads complete unchanged. The first verdict turns the rule off. What next prints for this task at each stage:



Choice ④Task-wide while no log exists; a task that starts logging midway backfills a pass row per reviewed page.


Alternative: per page; a page committed before the log counts as reviewed. No backfill, but a page committed unreviewed is never asked about.



A4 · The stop gate's base on a stacked branch




# scripts/agent-complete.sh:30-56, condensed
if [ -z "${HARNESS_BASE:-}" ]; then          ①
  others=remote branches minus */HEAD, upstream,
         */<this branch's name>              ②
  first=$(git rev-list --first-parent --reverse \
          HEAD --not $others | head -n 1)
  fork=${first:+$first^}   # none of our own: HEAD
  [ base is an ancestor of fork ] && base=$fork  ③
fi
# then, as before: records changed since $base or
# untracked; complete --base "$base" for each claim


    

  • ①An explicit HARNESS_BASE skips detection.
    • 

  • ②This branch's own remote copy is not "other".
    • 

  • ③The fork picks the records and is the --base for complete, so page order is judged from it too. CI's handoff is untouched; it already uses the PR's base.
    •

The three shaded rows end the same way: only uncommitted and untracked records are judged. A committed complete claim passes the stop and waits for PR CI, which judges every record.


Choice ⑤Detect the fork point from the remote branches; HARNESS_BASE overrides.


Alternative: no detection; document HARNESS_BASE=origin/<lower branch>. About 30 fewer protected lines, but a session that forgets the export is refused at every stop once CI evidence goes stale.



A5 · The author can't edit the log


In author mode an Edit or Write of any task's reviews.json gets (agent-hook.sh:403, case-folded): Blocked: the verdict log records reviews and only cargo xtask task-artifact verdict writes it; the author does not grade its own page. Both agents keep Bash (artifact-author.md:5, artifact-reviewer.md:5); a rewrite of committed rows shows as the second advisory.

Choice ⑥The stub is partial with no review answers


Plan's pick: partial, review absent. Valid at once, never blocks a stop, and handoff demands real answers before a PR passes.


Alternative: four "Not started" review answers, so a ticket-only PR passes handoff. Placeholders that satisfy a gate tend to survive to complete, which checks that answers exist, not that they're true.



A7 · The two doc passages a reader meets first


docs/ARTIFACTS.md, opening "How to produce a page"


"cargo xtask task-artifact next --task ID reads the task record, the pages and the task's verdict log and prints the one next step: author, review, rewrite, commit, build or complete. It advises and never blocks. It exits 3 when it also has a warning, such as a page edited after its last review. Completion does not read the log."


docs/COMPLETION.md, "At stop"


"On a branch stacked on another remote branch (an unmerged PR), it judges from where this branch's own commits start, so the lower branch's records are left to its own PR. A copy of this branch pushed under another name, a branch someone pushed on top of it, or a detached HEAD hides its commits the same way, leaving only uncommitted records to judge; PR CI still judges them all."
