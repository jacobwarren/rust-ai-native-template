Needs a code change · 1

After two rewrites, restoring the best version makes next ask for a fourth review

Plan said
A2, action best: "Three revise rows → Restore the best reviewed version, record --verdict best, commit."
Code does
page_step checks "last row is revise and the page changed" (router.rs:189-191) before "three revise rows" (:192-204). Restoring an earlier version changes the page, so the review arm wins.
Caught by
Three revise rows, page untouched: best, round 3. First draft restored: review, round 4. A fourth reviewer's pass is then refused with has used its two rewrites; commit the best version and record --verdict best. verdict best then records round 1, and next says commit.
Conservative fix
Swap the two arms so three revise rows always end in best. In two_rewrites_end_in_the_best_version, assert best after the restore; the test skips next there today. Until then the refusal points the agent to the right command, so the worst case is one wasted review, never a wrong row.

Code does
page_sha hashes the bytes on disk (router.rs:73-79), both in verdict and in the edited-after-review check (:289-304). Under * text=auto eol=lf Git stores and checks out LF, but the row keeps the hash of the CRLF bytes.
Caught by
A CRLF interview.html, passed and committed. In that checkout next gave no advisory. In a git clone of it: interview.html was edited after its Pass verdict; …, exit 3.
Conservative fix
Hash the bytes Git stores, as reference note 8 proposed: in page_sha, change CRLF to LF before the digest, which is what the repository's eol rule does to a text page. Extend a_crlf_page_that_git_calls_clean_reads_as_committed to check the page out again and expect no advisory. The git-status half of the CRLF work is right and stays.

What the code taught

  1. "Committed" has to come from Git, because a CRLF page hashes differently from what Git stores. 
    xtask/src/router.rs:171-174// Git's view, not a hash of the blob: eol=lf normalises a CRLF page that status calls clean.
let dirty = history::uncommitted(root)?;     // git status --porcelain -z --untracked-files=all
let path = format!("{}/{page}", artifacts::directory(id));
let committed = !dirty.contains(&path);

    The first draft compared blob hashes, and a_crlf_page_that_git_calls_clean_reads_as_committed fails on it. With this version a passed CRLF page moves next on to the following page. Gap 2 is the other half: the review hash has to match what Git stores too.

  2. The stop gate picks records by the net diff from the fork, not by the commit log. 
    scripts/agent-complete.sh:46-61, condensedfirst=$(git rev-list --first-parent --reverse HEAD --not $others | head -n 1)
fork=${first:+$first^}                       # none of our own: HEAD
[ base is an ancestor of fork ] && base=$fork
ids=$(git diff --name-only "$base" -- harness/tasks harness/task-artifacts; …untracked)

    Reference note 12 predicted this, and a fixture confirms it. This branch touches the lower branch's record and then restores it. The diff judges only this branch's two records, while a log filter would also list LOWER.json.
