1 · Context

On the last two tasks the orchestrating agent ran the page loop from the prose in docs/ARTIFACTS.md and drifted: pages were hand-edited after their final review and committed before their review finished, and verdicts lived only as prose in review.verification. The owner asked for a ticket skill and, from a talk on moving routing out of the model, for a small command that says what to do next. While this branch sat on an unmerged PR, the stop hook kept judging that PR's complete record and refused every stop once CI evidence went stale.

The interview settled the scope: the commands advise and never gate, completion does not read the log, and skills stay ceremony paths. The plan tabulates every action and stacked-branch situation, and the implementation notes list the four gaps the build found and fixed; neither is repeated here.

2 · The mental model

Routing moves from the agent's reading of a guide into a command that reads files. The gate that decides whether a task may be called complete is untouched.

Before · the agent routes from prose

docs/ARTIFACTS.md review loop
↓ the agent decides each step
author · reviewer · rewrite · commit
↓ verdicts as prose
review.verification in the record
↓
complete: record, pages, order, evidence

After · a command routes from files

task-artifact next: record + pages + reviews.json
↓ one step
JSON next, exit 0
↓ plus a warning
advisories, exit 3
↓ after each review
task-artifact verdict: one row, the page's SHA-256, a kept copy
↓ never read by
complete: record, pages, order, evidence

3 · Intuition: five behaviours a diff skim misses

01next asks each page the same questions in a fixed order, and the first yes wins

xtask/src/router.rs: page_step, condensed
no file                                          → author
no rows for this page:
    task has no reviews.json at all, page committed → done (reviewed before the log)
    otherwise                                    → review, round 1
≥ 3 revise rows and the last row is revise       → best
last row revise, page hash differs from it       → review, round revises + 1
last row revise, page hash equal                 → rewrite (n of 2)
last row pass or best:
    page and reviews.json both clean in git status → done
    otherwise                                    → commit
next walks the five discovery pages, then implementation.html (missing: build), then buy-in.html and quiz.html (missing: author), and stops at the first step; with none it says complete. A missing record gives record, and a small tier gives build.

02verdict numbers versions, not reviews, and refuses what the loop forbids

xtask/src/router.rs: verdict, condensed
round = revise rows for this page + 1          // 1 first draft, 2 and 3 the rewrites
pass | revise:
    refuse if the page's last row has this exact hash
    refuse if 3 revise rows exist                 // "has used its two rewrites"
    copy the page to target/artifact-reviews/<task>/<stem>.round<N>.html
best:
    refuse if the last row is already best
    refuse unless 3 revise rows exist and the last is revise
    round = the round of the row whose hash equals the page; no such row → refuse
Every flag is required, in this order: --task --page --verdict --reviewer --notes. The log is strict: schema_version 1, unknown fields refused.

03"The same version" means the same text after Git's line-ending rule

Hash
page_sha reads the file, turns every CRLF into LF, then takes SHA-256. The repository's .gitattributes is * text=auto eol=lf.
Commit
Whether a page or the log is committed comes from git status, not from comparing hashes with the stored blob.
Warn
After choosing the step, next checks every page in the log: if that page's latest row is pass or best and the page now hashes differently, it adds "edited after its … verdict". It also warns when the working log no longer starts with the rows committed at HEAD. main.rs exits 3 when the result is ok and advisories is not empty.

04The stop hook finds where this branch's own commits start

scripts/agent-complete.sh, condensed
base = merge-base(HEAD, ${HARNESS_BASE:-origin/main})
if HARNESS_BASE is unset:
    others = every refs/remotes branch except */HEAD, this branch's upstream,
             and any remote branch with this branch's own name
    first  = oldest commit on HEAD's first-parent line not reachable from others
    fork   = first^   (no such commit: HEAD)
    if base is an ancestor of fork and differs from it: base = fork
ids = task records and page folders changed since base, plus untracked ones
for each id whose record says "complete": cargo xtask complete --base base
The same base selects the records and is passed to complete, so page order is judged from it too. PR CI is unchanged: handoff there uses the pull request's base and judges every record.

05The log has one writer by convention, and the ticket skill writes a record the gate accepts

Hook
In author mode, agent-hook.sh refuses Edit and Write on any harness/task-artifacts/<task>/reviews.json, case-folded. The artifact-author agent runs that hook on Edit|Write|MultiEdit|NotebookEdit; it keeps Bash, which the hook does not cover.
Stub
write-ticket, identical for both hosts, writes a five-section ticket and then harness/tasks/<id>.json as partial, with the named tests as remaining actions, and runs coordination and next. The record is strict; Status is complete | partial | blocked.
