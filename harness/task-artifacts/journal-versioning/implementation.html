Deviations

6, all in steps 2–4

  1. 1 · Steps 2 to 4 landed as one change

    Plan said
    F: checksum, then format gate, then save refusal, as separate steps.
    Code revealed
    All three use Peek::parse, and load and the save peek share the bounded read(). Splitting them would have committed intermediate states with no meaning of their own.
    Choice
    One change. The order inside load is as planned.

  2. 2 · The strict Envelope stays, with its hash field unused

    Plan said
    C: Envelope and Journal unchanged and strict.
    Code revealed
    The peek now checks the digest, so Envelope.sha256 would be a field that is never read.
    Choice
    Keep deny_unknown_fields for readable formats and rename the field #[serde(rename = "sha256")] _sha256 (store.rs:20-23). A v1 file with an extra top-level key is still invalid_store, as before.

  3. 3 · Messages say "format 1" when there is only one

    Plan said
    D: "this build reads formats 1 to 1".
    Choice
    A formats() helper says "format 1" when oldest equals newest and "formats 1 to 2" otherwise (store.rs:75). Load and save keep their own sentences, both built through too_new(). Wording only.

  4. 4 · A v1 file that fails both digest and parse is corrupt_store

    Plan said
    Nothing for this case.
    Code revealed
    A format-1 file whose raw digest fails and whose data does not parse as a strict Journal cannot be re-serialized for the fallback.
    Choice
    corrupt_store, not invalid_store: the digest is the first gate that fails. The same data with a correct digest reaches the strict parse and is invalid_store.

  5. 5 · The size check moved into load_from

    Plan said
    C: load_from(bytes, newest, session) takes over the body after the read.
    Choice
    The 256 KiB check runs first inside load_from (store.rs:197-199), so tests that call it directly cannot skip it.

  6. 6 · An oversized board.json is not replaced

    Plan said
    A3: save replaces a missing, unparseable or older file; only a peeked newer format refuses.
    Code revealed
    A file over 256 KiB cannot be peeked, so a newer build's large board counted as damaged and was overwritten.
    Choice
    Save returns capacity and keeps the file. A damaged file that large has to be removed by hand; this build could not load it anyway.
