A1 · Ship a real format-2 command now, or only the mechanism?

Why. Builds already shipped answer an unknown command with invalid_store (blindspot 01). Only builds that contain the new reader can refuse a newer file clearly, so the reader should ship one release before any v2 writer does. Rename is also not a store change. It adds a variant to the enum that execute, replay and capture share (protocol.rs:23-24). It needs a Board::rename that crates/domain/src/board.rs lacks, and the property model's _ => false arm (tests/properties.rs:59) would have to learn it.

Testing "accept up to ours" without a v2 command. The gate is a pure check_format(found, oldest, newest). The load body takes newest as a parameter: load calls load_from(bytes, JOURNAL_FORMAT). A forged v2-add-only.json must load through load_from(.., 2) and be refused by load_from(.., 1). introduced_in has no wildcard arm, so a new variant does not compile until it names its format.

The Rename task still has to reject a file that declares format N but holds a command from N+1. While every command is format 1, that check can never fire, so it cannot be tested here.

A2 · Raw-byte hashing vs. a hand-reformatted v1 file

The digest is computed over the re-serialized struct today (store.rs:131), so a pretty-printed or key-reordered v1 file loads. Under lean Q6 it would not. Files this build wrote are safe: their raw data span is byte-identical to the re-serialization (evidence below).

The fallback is about ten lines and adds no new constraint: the v1 strict parse already depends on today's Command serialization. The next save rewrites the file compactly.

Run on this branch. I saved a 598-byte board with today's driver. Its titles included quotes, a backslash, </script>, emoji, CJK, a no-break space and 120 characters. The SHA-256 of the bytes between {"data": and ,"sha256" equals the stored hash, because save serializes Journal with the same compact serde output on its own and inside Envelope (store.rs:83-84). A scratch crate using serde_json 1.0.154 with raw_value read each file through a lax Peek. The pretty-printed and reordered copies failed the raw digest but passed the re-serialized one, and today's driver loads both. The edited copy failed both digests.

A3 · Save finds a board.json it cannot peek

Lean Q5 makes save refuse a newer file. It leaves open what save does with a truncated or non-JSON file (interventions #5).

Either way, an I/O error other than "not found" fails the save with storage_io. Save refuses on the format number alone, without checking the checksum. The writer lock (store.rs:56) keeps the file stable between the peek and the rename.

pub const JOURNAL_FORMAT: u32 = 1;1
pub const OLDEST_JOURNAL_FORMAT: u32 = 1;

impl Command {
    pub(crate) const fn introduced_in(&self) -> u32 {
        match self {2
            Command::Add { .. } | Command::Complete { .. }
            | Command::Remove { .. } | Command::Undo {} => 1,
        }
    }
}

// crates/engine/src/store.rs
fn format_for(commands: &[Command]) -> u32 {
    commands.iter().map(Command::introduced_in).fold(1, u32::max)
