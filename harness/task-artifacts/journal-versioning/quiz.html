The old store also reused version, the protocol's code for a bad request version, so a client could not tell "your request is old" from "your file is new".

Intuition: three ideas carry the whole change

Everything in the diff serves one of these.

1 · Date the file before you read it

Every format keeps data and sha256, with data.schema_version inside. A lax Peek reads only those, so any build can verify and date a future file without understanding its commands.

That needs a digest over the bytes as stored: re-serializing the journal needs every command understood.

2 · Write the lowest format the journal needs

Each command names the format that introduced it (Command::introduced_in; with no wildcard arm, a new variant will not compile until it does). Save writes the highest over session.journal(), never below the oldest format the build reads.

So a board that never used a newer command stays readable by older builds.

3 · Never overwrite what you cannot date

Before staging a save, the store reads the existing board.json. A newer format, or a file too large to peek, is left alone.

A missing, truncated or unparseable file is still replaced: saving is the in-app way to recover a damaged board.

The writer sets schema_version to format_for(commands) (store.rs:53), the highest introduced_in but never below OLDEST_JOURNAL_FORMAT, so it cannot write a file it would then refuse. It serializes data once into a RawValue, hashes exactly those bytes and writes them (store.rs:144-158). For format 1 the raw bytes and the old re-serialization are identical, so v1-board.json re-saves to the same 269 bytes.

Also: JOURNAL_FORMAT and OLDEST_JOURNAL_FORMAT (both 1) in lib.rs; load_from takes the newest readable format, so a test can act as a format-2 build; discover reports "journal_formats":{"reads":[1],"writes":[1]}; DRIVER.md documents the gates. New store tests pin the v1 bytes, the pretty and edited v1 copies, every v2 fixture on load and save, the format bounds, raw-span hashing and recovery over a truncated file. The old corrupt, future and oversize test now asserts exact codes.

What this leans on, and what it leaves for later

None blocks the merge.

Replay never sees the format.

load_from hands only data.commands to Session::replay, which runs today's execute on each. The journal keeps input as typed: after a load the fixture's first command is still " Review "; only the board shows Review.

No check that a format-N file holds only format-N commands.

It cannot fire while every command is format 1; it comes with the first format-2 command.

Builds from before this change are unchanged.

They still answer a newer file with invalid_store or version and overwrite it, which is why the reader ships before any writer of format 2.
