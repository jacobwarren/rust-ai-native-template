Already settled by the code not asked

Older builds can't skip commands they don't know

Load rebuilds the board by re-running every journaled command in order (Session::replay, lib.rs:107–119). next_id advances on every add (board.rs:65–71) and undo pops whatever the previous command pushed (lib.rs:82–86). Dropping one unknown command would renumber later tasks or make a later undo restore the wrong board. Refusing is the only safe behavior, so a tolerant reader is off the table.

There are no unversioned boards to detect

Every save has written schema_version: 1 inside the checksummed data object since the store was added (store.rs:79–82). Any existing file is identifiable as v1. Missing-version files don't need a special path.

A refused load already leaves the live board alone

Replay builds a fresh candidate and swaps only on success (lib.rs:111–117). corrupt_future_and_oversize_files_do_not_change_live_state (store_tests.rs:98) covers it. Versioning needs no new rollback logic, only better refusals.
