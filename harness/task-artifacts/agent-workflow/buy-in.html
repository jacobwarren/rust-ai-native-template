Small fixes skip the page ceremony; the page workflow becomes skills and subagents

The prompt

Package the plan, the implementation notes and the evidence into a single doc I can share to get buy-in on shipping task tiers, agent skills and subagents in this template. Lead with the demo.

Today every task in this template owes eight HTML review pages, each written by its own agent and checked by another, even a one-line README fix. This change adds a small tier: a task of at most 100 changed lines that stays clear of policy, dependency and ceremony files owes its task record and review answers, but no pages. The gate measures the branch, so a task cannot call itself small and then grow. The same change turns the page author and reviewer briefs into skills both agent hosts can load, defines the author and reviewer as subagents, and trims the agent map.

The repository owner asked for this work and delegated the open design decisions to the agent's recommendations. Every decision in section 05 is the agent's call, listed so an approver can overturn it. Nothing on this page has been approved yet.

02Why ship it

The last task merged into this template added default agent hooks. Its merge changed 3,619 lines of review pages and 1,543 lines of everything else: code, tests, config and docs, leaving out its task record and receipt. Its recorded review verdicts imply at least 40 page-author and page-reviewer runs for those eight pages, counting one author and one reviewer per round; the agent's own estimate, counting research and reruns, is about 50. Under today's rules a one-line README fix owes the same ceremony (case 1).

The ceremony is not waste where it counts. On that task, its page reviews and checks found real defects before merge, recorded in that task's record and notes: a guard script error that Codex let through (fixed by an exit trap), and hooks that silently ran a stale xtask binary. On this task the notes caught five departures from the plan, one of them a blocked small task that could stop past the size limit. So the tier is drawn around risk as well as size: anything touching the gate, the hooks, the CI workflow, dependencies or the ceremony's own definitions stays standard at any size (case 3). This change itself is standard and carries all eight pages.

The skills and subagents make the remaining ceremony cheaper to run correctly. The author and reviewer briefs were Markdown files an agent had to be told to read. As skills, both hosts list them by name and description and load the body when needed. As subagents, the model split (author on Opus, reviewer on Sonnet) and the tool limits are configuration instead of a paragraph to remember. The agent map, AGENTS.md, drops two procedural paragraphs to the guides that own them and gains one rule: prefer cargo, clippy and xtask over new scripts, and add no manual steps or approval gates a task did not ask for.

03What approvers will ask

Can an agent just label a large change small?

No. The record's label is checked against the branch at handoff and complete, and CI runs handoff on every pull request (.github/workflows/ci.yml:41). The count is added plus deleted lines against the merge base, moves count on both sides, uncommitted and untracked files count, and any binary file refuses (xtask/src/size.rs; cases 1–3). Task records, receipts, review pages and docs/plans/ are bookkeeping and do not count. A task that outgrows the tier is split or restarted as standard on a new branch, because discovery pages must come before the first code commit. What the count cannot see is in section 06.

Could a small task weaken the gate itself?

No. Every protected policy path (xtask/, scripts/, .github/, .claude/, .codex/, goldens, AGENTS.md and the other policy files), any Cargo.toml at any depth, and the ceremony's own definitions (docs/ARTIFACTS.md and the skill and agent folders) force a standard task (case 3; forces_standard in xtask/src/size.rs). The limit of 100 is a constant in that file, so changing it is itself a standard task with a policy receipt.

Does the page-author subagent really stay in its folder?

Only for its Edit and Write tools, and only on Claude Code. The author's own hook refuses any edit outside harness/task-artifacts/<task>/ except scratch files outside the checkout, including target/debug/xtask, the binary the default hooks run (case 5). Claude Code runs a subagent's hooks only in a trusted workspace and never in non-interactive -p mode (from its docs). The author's Bash tool is not confined by this hook; the default guard and the brief still apply there. Codex cannot limit a role's writes at all, and the Codex author's instructions say so.

Will the hosts actually load these skills?

The files follow each host's documented layout: .claude/skills/<name>/SKILL.md for Claude Code and .agents/skills/<name>/SKILL.md for Codex, with name and description frontmatter. The harness forbids symlinks, so each skill is kept twice and cargo xtask docs (run by check fast and CI) refuses copies that differ or names that do not match their folder (case 4). Neither host has been observed loading them in a live session; that is from docs only. Description length is not checked; all three are under Codex's 1,024-character limit today.

06Limits, and what still needs the owner

The count is lines, not meaning

Dense or minified lines count once; one feature split across several small branches passes each gate. CI and human review are the check on both.

Author confinement is partial

Edit and Write on Claude Code in a trusted workspace only. Bash is unconfined; a symlink outside the checkout that points into it reads as outside. Codex roles have no write limit.

Not observed in a live host session

Skill loading, the subagents' model and tool settings, and Claude Code refusing a Write after the author hook exits 2 all come from host docs. The hook's own exit codes and messages were observed (case 5).

The case fold depends on Git's setting

It applies only where core.ignorecase is true, the default on macOS volumes. Where Git compares case, other spellings are other files and nothing changes.

What the owner still decides

  1. Accept the policy change. It changes the completion gate, the hook script and agent configuration, all protected; the branch's transition receipt explains it for review.
  2. Accept or change the limit of 100 lines.
  3. Decide whether a live check comes first: load a skill and run the author subagent in a trusted Claude Code session, and trust .codex/ to try the Codex roles.
  4. Merge. The default hooks ask before an agent's gh pr merge.
