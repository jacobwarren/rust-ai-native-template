Semantics map: the artifact gate as the reference for tiers, skill copies and the author hook

The existing artifact gate (artifacts::check, check_written and order, called from completion::task, completion::validate and artifacts::guard), the protected-path table in transitions.rs, the docs catalog checks in checks.rs, and the default guard in scripts/agent-hook.sh already behave the way the tiered gate, the skill copies and the author's write hook should: decide from a path table, read the branch's history, and refuse with a named fix. Read them and show me a semantics map, with matched excerpts, gotchas and edge cases, so I can confirm you understood it before you build anything.

read xtask/src/{artifacts,completion,task_record,history,transitions,checks,repo}.rsscripts/{agent-hook,agent-complete,agent-artifact-write}.shdesign interview.html

The design being mapped is the one the interview settled: an optional tier, a 100-line size check from the merge base with a list of paths that force standard, byte-identical skill copies, and an author hook that lets Edit and Write through only under harness/task-artifacts/ or outside the repository.

1What the reference actually does

  • Decides from path tables, prefix or exact. administrative() (artifacts.rs:33-43) marks records, receipts, pages, docs.json and gaps.json as not product. protected() (transitions.rs:62-64) has 7 prefixes and 11 exact files, copied into agent-hook.sh:14-15 and kept equal by a test (transitions.rs:221-225).
  • Reads history by commits or by tree. order() reads commits (history.rs:48-65), which list nothing on a CI merge ref (blindspot 02). transitions::required (:103-123) and the stop hook compare the merge base with the working tree; size does too.
  • Refuses with a named fix, e.g. missing {page}; see docs/ARTIFACTS.md (artifacts.rs:102) or DOC004 … add ownership and verification to harness/docs.json (checks.rs:160), collected beside review and CI errors (completion.rs:37-39).
  • The hook is a deny-list that fails closed on any exit but 0 or 2 (agent-hook.sh:8-11), except outside a Git checkout, where it allows before any mode runs (:86-87).

Deliberately fail closed outside Git. The guard has nothing to protect there; without a root the author mode cannot tell this repository from anywhere else, so it blocks.
.. resolves first. observed harness/task-artifacts/x/../../../xtask/src/main.rs is blocked as xtask/src/main.rs. Resolution is lexical; a symlink in the folder already fails verify and repo::files.
Outside is "", and target/ stays blocked. observed /tmp/elsewhere.txt and ../outside.txt pass; target/debug/xtask, which agent-artifact-write.sh:7 and the post-edit check (agent-hook.sh:347-351) execute, is blocked, so screenshots go through Bash. On this case-insensitive volume XTASK/src/main.rs is xtask/src/main.rs: the guard is silent today, the allow-list blocks it. Case costs a false block, never a bypass.
Folder-wide, Edit/Write only, Claude only. The hook can't know the task ID, so another task's pages are writable; Bash is uncovered (blindspot 07). It lives in the agent file's hooks: PreToolUse, and Claude runs a project agent's frontmatter hooks only after the folder's trust dialog is accepted; a -p session does not count as trusted, and an untrusted author still runs, unconfined. Codex agent files set no per-agent sandbox or write-path limit, so on Codex the author has no path confinement.

4Edge cases

CaseWith the design
Leave a new .rs file untrackedAbsent from the diff, counted from ls-files -o with git's line rule.
Fix a typo in a skillStandard (ceremony list), plus a receipt for the .claude/ copy; parity drags both copies along.
README typoSmall at 1 line; still needs a changed record (completion.rs:160-161) and its four review answers.
Two task records on one branchEach task() measures the whole branch diff, so a standard sibling's code makes the small one fail.
The author runs in a Git worktreeThe root is the worktree, so the main checkout's xtask/src/main.rs reads as outside and is allowed (observed with the sketch).
Dense or minified linesResidual: a 40 KB one-line JSON counts as 1.
A feature split across small branchesResidual: undetectable from inside one branch.
