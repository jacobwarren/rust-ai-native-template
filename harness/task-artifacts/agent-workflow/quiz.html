1 · Context

Every task that touched product code owed eight HTML pages, each with its own author and reviewer: sixteen or more agent runs for a one-line fix, while AGENTS.md step 4 said "Small changes need no ceremony". The owner asked for the context-engineering version: rules say what to do, hooks always run, skills load on demand, subagents isolate context, no red tape.

2 · The mental model

The tier is a promise written into the task record at the start; nothing infers it. Gates that know the merge base hold the branch to it.

Before · one path for every task

task record
↓
5 discovery pages before code, then notes, buy-in, quiz
↓ 8 authors + 8 reviewers
complete: pages present, commit order read

After · the record picks the path

task record · "tier" (absent = standard)
↓ standard
the same eight pages
↓ small
no pages; size::check_small at handoff and complete
↓ too many lines, or a forcing path
refused: narrow it, or restart standard on a new branch

Only handoff, complete and agent-stop hold a base, so only they run size::check_small; coordination, task-artifact guard and check parse the tier but do not measure. Growth surfaces at the next handoff, which CI runs on every pull request. There is no same-branch switch to standard: its discovery pages would have to precede a code commit that already exists.

3 · Intuition: four behaviours a diff skim misses

01The count is Git's own, with rename detection off, and administrative paths skipped first

What
size::changes takes added plus deleted per path from git diff --numstat --no-renames BASE, committed or not, plus each untracked file's line count. A binary file is a problem by itself.
xtask/src/size.rs: check_small
for (path, lines) in changes(root, base)? {
    if artifacts::administrative(&path) { continue; }
    if forces_standard(&path) { problems.push(… "is a policy, dependency or ceremony path") }
    match lines { Some(n) => total += n, None => problems.push(… "is a binary file") }
}
if total > SMALL_LINES { problems.push(… "changed lines exceed the small limit") }   // SMALL_LINES = 100
The first test skips a path entirely: task records and pages, transition receipts, the docs and gap registers and anything under docs/plans/ are neither counted nor checked (artifacts::administrative).

02Some paths force a standard task however few lines they change

transitions::protected(path)       // PREFIXES.any(|p| path.starts_with(p)) || FILES.contains(&path)
    || path == "Cargo.toml" || path.ends_with("/Cargo.toml")

Three lists over repository-relative paths. The first is the table that already demanded transition receipts; it names only the root manifest, so size.rs adds the highlighted line for crate manifests. The ceremony list stops a small task rewriting what small means.

03The record and the blocked stop both fail closed

Tier
#[serde(rename_all = "snake_case")] enum Tier { Small, #[default] Standard } in a #[serde(default)] field on Task. Older records stay standard and the schema stays at 6. Every command that reads a record parses it this way.
Stop
A blocked task may stop while harness/gaps.json does not parse only when its review answers, page check and size check are all clean. Otherwise completion::task returns the register's error at once, before it gathers the task's own errors.

04Skills live twice, and the author's write limit is a hook with known edges

Skills
Claude Code reads .claude/skills/, Codex reads .agents/skills/, and the harness rejects symlinks, so author-artifact, review-artifact and the new add-product-command each exist twice. checks::skill_copies runs two independent checks: DOC007 compares each file with its twin byte for byte, and DOC008 reads the frontmatter of every SKILL.md in both trees and wants its name: to equal its folder.
Agents
artifact-author (Opus) runs agent-hook.sh author claude before every Edit and Write; artifact-reviewer (Sonnet) has no Edit or Write but keeps Bash. Codex roles have no write limit.
Hook
author makes the path relative to the checkout Git reports for the event's cwd, as text, without resolving symlinks. Inside, only harness/task-artifacts/<task>/<file> passes. Outside, it finds the main checkout through Git's shared directory and blocks a path there, which can only happen when the session runs in a linked worktree; every other outside path passes, for screenshots and scratch files.
