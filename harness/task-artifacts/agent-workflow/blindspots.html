Write a failing test for each of the seven commands with a small task that has no pages before changing any of them.
Landmine02

git diff --numstat misses the three cheapest ways to grow a diff

A branch commits a move of a 225-line file with one edited line plus a 4 KB binary, and leaves one new .rs file untracked:

$ git diff --numstat BASE
-	-	crates/app/blob.bin
1	1	xtask/src/{workflows.rs => flows.rs}
$ git diff --numstat --no-renames BASE
-	-	crates/app/blob.bin
225	0	xtask/src/flows.rs
0	225	xtask/src/workflows.rs
# the untracked file appears in neither

Rename detection is on by default (git 2.55 here), so a move counts as 2 lines, and its path is printed as {a => b}, which never matches a prefix in administrative() or the protected lists. Binaries print - instead of a count, so a parser has to decide what that means. A GitHub merge ref behaves the same: merged with --no-ff, plain git diff --numstat BASE HEAD still prints 1 1 xtask/src/{workflows.rs => flows.rs}, and only --no-renames shows 225/225. The repo already sets the precedent: history::commits passes --no-renames (history.rs:58). On that merge ref the same function's --first-parent --no-merges log lists no commits at all, which is gap artifact-gate-holes: a rule that reads commits passes vacuously in CI, so the tier has to read the tree.

Untracked files are already covered at completion: order() refuses while history::uncommitted (history.rs:79-96, --untracked-files=all) lists any non-administrative path (artifacts.rs:140-148). The gap is everywhere order() doesn't run: partial handoffs, and a small tier if its check returns before order().

Why it bites: a small-tier check written the obvious way lets a large move or a vendored binary through as "small", and an unstaged file too wherever order() is skipped. The diff also belongs to the branch, not the task, so two records on one branch share one count. Splitting a big change across several small branches can't be detected from inside one branch, by design.

How should moved lines count?
Landmine03

Once a small task has a product commit, it can never become standard on that branch

order() requires every discovery page to exist at the base or to be committed before the first product-code commit (artifacts.rs:166-172). A small task's first code commit comes before any pages, and the rule reads the earliest commit that touched each page (touched, artifacts.rs:160-165), so no later commit can satisfy it. The existing test discovery_must_be_committed_before_the_first_code_commit (xtask/tests/artifacts.rs:96-107) asserts exactly this case. Extended to code, then discovery pages, then a second slice with notes, then final pages with blindspots.html re-touched, complete still answers:

task HTML artifact: blindspots.html must be committed before the first product-code commit

Until then nothing warns: order is checked only when the record says complete and a base is given (artifacts.rs:105), so a partial "standard" task with pages written late passes handoff.

Rewriting history is ruled out after a push. .claude/settings.json denies Bash(git push --force *), Bash(git push -f *) and Bash(git push --force-with-lease *), and agent-hook.sh:275-277 blocks force-pushes on both hosts.

Why it bites: the failure arrives at the completion claim, after the work is done, and the message names a page rather than the tier switch that caused it.

Convention04

tier is rejected until xtask knows it, and eight pages are built into the fixtures and the readiness list

$ xtask coordination      # default-hooks.json with "tier": "small" added
{"error":"unknown field `tier`, expected one of `schema_version`, `id`, ... at line 79 column 8","ok":false}

Task is deny_unknown_fields (task_record.rs:16-17), so the field, #[serde(default)], and the record that uses it must land in the same commit. Leave schema_version at 6: read accepts 1-6 (line 67), review_errors requires exactly 6 (line 124), and validate branches on >= 6.

The test helper Fixture::task() (tests/support/mod.rs:107-118) commits all eight pages before returning a record; its 22 call sites in completion.rs, gap_discovery.rs and hooks_stop.rs never exercise a task without pages. The task-artifacts requirement in the protected harness/readiness.json lists test names, including completion_requires_eight_pages_carrying_the_stylesheet_inline, and readiness::assess marks it unverified when a listed name is missing from the CI log (readiness.rs:77-90).

Why it bites: a tier test left out of readiness.json proves nothing to the readiness gate, and renaming a listed test leaves the requirement unverified.

Add tier as Option with serde(default) and no schema bump. Give the test fixture a way to build a task with no pages. Add the new tier tests to harness/readiness.json's task-artifacts list in the same change and include it in the transition receipt, and don't rename the existing eight-page test.
Landmine05

One skill in two folders: a symlink breaks every check, and copies break links and protection

$ ln -s ../.claude/skills .agents/skills
$ xtask docs; xtask coordination; xtask env
{"error":"source symlink …/.agents/skills is unsupported; use a real file","ok":false}   # all three

repo::files (repo.rs:39-45) returns an error, not a lint, so one symlink stops docs, coordination, readiness and the source fingerprint. Both host folders sit three levels deep, so identical copies can share a ../../../docs/ARTIFACTS.md link. docs/skills/ is two levels deep and can't be a byte-identical third copy. Protection is uneven: the default guard returns a policy note for cp … .claude/skills/x/SKILL.md and {} for the same copy into .agents/skills/, because PROTECTED_PREFIXES (transitions.rs:39-47) includes .claude/ but not .agents/.

Why it bites: every wording change to a Claude skill becomes a policy change that needs a receipt, while the Codex copy needs none. That's the kind of red tape item 5 is meant to remove, and a parity check only partly makes up for it.

Landmine07

"Writes only under harness/task-artifacts/" is enforceable for Edit/Write on Claude, and nowhere else

Claude Code: tools takes tool names with no path scope, so confinement means a per-agent PreToolUse hook that exits 2 (sub-agents docs). That hook does enforce Edit/Write. But a project agent's frontmatter hooks run only after the folder is accepted in the workspace trust dialog, and a -p session never counts as trusted, so a headless author runs without it. The author brief requires Bash, though: it clones the repo, runs cargo xtask task-artifact style (which writes target/artifact-style.html, artifacts.rs:81-84) and runs the screenshot script under target/. If a Bash path filter reuses the guard's parser, it sees only redirects plus mv rm tee truncate cp install sed and git checkout/restore (agent-hook.sh:198):

python3 -c "open('xtask/src/main.rs','w').write('x')"   -> {}   (allowed, no note)
perl -pi -e s/a/b/ xtask/src/main.rs                    -> {}
git apply fix.patch                                     -> {}
echo x > xtask/src/main.rs                              -> policy note

A read-only reviewer conflicts with step 2 of its own brief: "Run builds and tests in a clean copy." Without Bash it can't check claims, and the brief says that is not a pass.
