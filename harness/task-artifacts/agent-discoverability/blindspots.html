Landmine01

Three arms take --help as a value before any help code can see it

dispatch tries its arms in order (xtask/src/main.rs:73-265). Three bind a free word: ["check", profile] (217), ["workflow", id] (222) and ["release", scope, "--report", path] (232). The verdict catch-all ["task-artifact", "verdict", ..] (147) answers before the fallback on 264 does, and ["run", "--", tail @ ..] (239) must hand --help to the app.

Why it bitesAdd help as a new arm or inside the _ fallback and check --help still says "unknown profile: --help". The ticket's tests still pass, because none of them asks about check, workflow or release.
Read --help/-h from the argument list before the match in dispatch, scanning only up to the first `--`, so the check, workflow and release arms can never bind it as a profile, workflow id or scope. Add check --help, workflow --help and release --help cases to help_narrows_to_the_commands_asked.

Landmine03

The stop hook tells a refusal from a crash by the first line of xtask's JSON

main prints an Ok value pretty (main.rs:29, println!("{value:#}")) and an Err compact on one line (main.rs:43). scripts/agent-complete.sh:78 counts exit 1 as a refused claim only when the first line is exactly {, which is the gate's pretty output. Anything else is "could not run". Usage on wrong arguments goes down this path whenever the hook's complete call (line 76) is malformed.

Why it bitesReturn usage as Ok(json!({"ok":false,"usage":…})), or pretty-print errors so a list of usages reads well, and a broken complete call becomes a "refused" claim whose advice (regenerate CI evidence) cannot fix it. No test pins this: stop_blocks_a_claim_when_the_gate_cannot_run (xtask/tests/hooks_stop.rs:46) uses a stub that writes to stderr and exits 101.
Keep wrong-argument errors on the Err path in main.rs, printed as one compact line: put the usage inside "error" or in a sibling field of that same object, never in an Ok value. Add a stop-hook test where the gate prints a one-line JSON error and exits 1, and assert the hook says "could not run".
History04

agent-stop was the hook gate until 41c49e0, and it is still a real verdict

Before commit 41c49e0 the stop hook was opt-in and ran cargo xtask agent-stop --task "$HARNESS_TASK_ID" --base "$HARNESS_BASE" (line 9 of the script's previous version). 41c49e0 replaced that with a loop that runs complete for each task record changed on the branch that says complete (agent-complete.sh:58-76), measured from the fork point when the branch is stacked (34-56). The help string on main.rs:98 did not change. The command itself still does more than "not the hook":

excerpt · xtask/src/completion.rs:253-268, trimmed
pub fn agent_stop(root, id, revision, report) -> Result<Value> {
    let record = task_record::read(root, id)?;
    if record.status == Status::Complete {
        return complete(root, id, revision, report);      // the gate the hook runs
    }
    let task = task(root, id, &base, Some(report), false)?;
    if task["reconciliation_pending"] == true {
        return Ok(json!({"ok":true, "kind":"blocked_handoff", …}));
    }
    let transitions = transitions::check(root, &base, report.is_file().then_some(report))?;
    Ok(json!({"ok": task ok && transitions ok, "complete":false, "kind":"handoff", …}))
}

Its callers today are tests only: xtask/tests/gap_discovery.rs:53, completion.rs:108 and 127, tiers.rs:93 (grep for agent-stop across xtask, scripts, docs and both hook configs).

Why it bites"Not used by the hook" tells an agent what the command isn't. A new hook-flavoured label repeats the drift that started here. Sketch of a true entry, not yet written: "One task's stop verdict, by hand: complete's gate when the record says complete, otherwise a partial or blocked handoff check (the report may be missing). The default stop hook runs complete instead."
Describe agent-stop from completion::agent_stop (completion.rs:253): complete's gate when the record says complete, otherwise a partial or blocked handoff check that tolerates a missing report. Say the default stop hook (scripts/agent-complete.sh:76) runs complete. In agent_stop_help_names_the_hook_that_runs, assert the script contains `complete --task`, not only that it lacks agent-stop.

Convention08

Nothing tests help today, and the new tests have three constraints

A grep for unknown command or extra, cargo xtask help and "commands" across xtask/, scripts/, docs/, README and AGENTS finds them only in main.rs and this task's plan. Nothing caught the stale agent-stop string, and nothing will catch the next one unless the new tests do.

  • Names. Readiness counts a test as passed by matching test NAME ... ok lines in the CI log (xtask/src/readiness.rs:151-157). The four names join the 29 under completion in harness/readiness.json as bare integration-test names. A unit test inside main.rs would be reported as tests::NAME.
  • Workspace root. dispatch finds the root before it reads any argument (main.rs:71; repo.rs:7-13 needs harness/config.json and Cargo.toml above the working directory), so help fails outside the workspace. Fixture::new (xtask/tests/support/mod.rs) provides both. In a fixture, run -- --help is cheap: there is no starter-app, the build fails, and the reply is the build record rather than help.
  • Size. SIZE001 fails any .rs file over 400 lines (checks.rs:82, harness/config.json:3, a protected file). main.rs is at 266, and the table takes 24 of them.
