1What the arm actually does

A verdict call passes three checks, and only the first answers with usage

the reference

1 · Shape

match in dispatch · main.rs:110-127, 147-150
  • Exactly 16 positional words, flags in one order.
  • Anything else that starts task-artifact verdict gets verdict's usage.
  • task-artifact verdikt misses both arms and gets the generic error (264).
→

2 · Stdin

piped_notes · main.rs:54-68
  • Only when the notes word is -.
  • Refuses more than 64 KiB, non-UTF-8 input or blank input.
  • Runs before any value is checked: with --task nosuch and empty stdin, the stdin error is the one reported (§4 row 8).
→

3 · Values

router::verdict · router.rs:106-133
  • Task record, page name, verdict word, reviewer, findings count, model, page on disk.
  • Each error names its field (--findings two must count…), with no usage.
  • Then a row goes into reviews.json.
  • Two arms, one command, and their order matters. The full 16-word slice comes first (main.rs:110). The catch-all ["task-artifact", "verdict", ..] comes after it (147), so it sees only calls that do not fit. A missing flag, a reordered flag, an extra word and --help all get the same message (captured, §4).
  • It was written as a migration note. 78e8fee (2026-11-04) made --model and --findings required and added the catch-all in the same diff. Its commit message says the flags come "in the order --reviewer --model --findings --notes". That is why the message ends "in that order; --model and --findings are required".
  • The message is a hand-made second copy of the help key. The pattern in the message (148) matches the help key on line 96 word for word. Both 78e8fee and a766413 (which added TEXT|-) edited the two copies in step. Nothing checks that they stay equal.
  • A completion test pins part of its wording. verdict_records_findings_and_model sends the old six-flag form and asserts the error contains --model and --findings are required (xtask/tests/router.rs:326-349). harness/readiness.json:151 lists that test under completion. The interview's Q6 said a grep of xtask/tests finds no test of this text. That holds for the opening words, but this test asserts the closing clause. Removing the arm, which is the interview's call, fails this test unless its assertion changes (sign-off choice 1).

pub fn wrong_arguments(words: &[&str]) -> UsageError {
    // the longest run of typed words that some
    // entry starts with; placeholders match any word
    let usage = (1..=words.len()).rev()
        .map(|n| starting_with(&words[..n]))
        .find(|m| !m.is_empty())1
        .unwrap_or_default(); // unknown first word: none
    UsageError { usage } // keys of table()3
}
1The prefix is the rule. ["task-artifact", "verdict", ..] is "the commands that start with the same words" (plan, Scope), written out by hand for one entry. The sketch tries the longest typed prefix first. That is the interview's Q5 call: task-artifact nxt gets all six task-artifact usages and complete --task X gets complete's. Placeholders such as ID must match any word, which only works once the keys use one spelling (blindspot 02). The verdict key adds a spelling that card did not list: alternations, pass|revise|best and TEXT|-, the only | in any key. Read as literal words, they never match a typed pass. The shorter run before them still picks out verdict alone, so the reply is the same either way.
2Placement carries the meaning. The catch-all only ever sees calls the full arm rejected, because it comes second. The fallback keeps that by staying last. Arms that bind a free word (["check", profile] 217, workflow 222, release 232) match before any fallback, so check nonsense never gets usage. See §4 row 10 and sign-off choice 2.
3The text comes from the table, not a copy. Today's pattern matches line 96 exactly because two commits edited both copies. Reading the keys from table() keeps them equal by construction. 3Behaviours

Preserved, deliberately changed, dropped

Preserved exactly

  • Err path, one line, exit 1: main.rs:42-45, so the hook's reading holds (note 7)
  • Catch after the arms that fit: the fallback stays last, as 147 sits after 110 (note 2)
  • Usage words = help key words: the same text the help table shows
  • Value errors stay where they are: router.rs:115-133 keep their messages, with no usage
  • --notes - reads stdin only after the shape matches: main.rs:129-133

Deliberately changed

  • Text source: a hand copy becomes a lookup in table() (note 3)
  • Prefix: two fixed words become the longest typed run, for every entry (note 1; interview Q5)
  • verdict --help: an error with exit 1 becomes the verdict help entry with ok:true
  • --notes --help / -h: stored as notes today, a help request after (note 4; interview Q3)
  • Reply: gains a usage array beside error (note 8; interview Q2)

Dropped

  • The verdict-only arm, main.rs:147-150 (interview Q6)
  • "--model and --findings are required": a 78e8fee migration note. The usage shows both flags. router.rs:348 must change (choice 1)
  • "in that order" as verdict's own clause: order matters for every command (complete with reordered flags gets the generic error, interview Q1), so the generic usage error says it once
