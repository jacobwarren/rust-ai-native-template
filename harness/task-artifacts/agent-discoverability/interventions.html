Brainstorm the intervention · agent-discoverability · before code

Eleven places cargo xtask could stop misleading a fresh agent

The prompt
Here's the problem: A fresh agent opened 30 files to learn the harness, was told any non-ceremony skill changes freely when investigate must also match its seed, was told agent-stop is the hook gate when the stop hook runs complete, and got no help from cargo xtask task-artifact next --help. Search the codebase and brainstorm the places we could intervene, from cheapest to most ambitious. I'll tell you which ones resonate.

Two of the three correct answers are already written down, just not where the agent looked. docs/COMPLETION.md:172 says the stop hook runs complete, and README.md:110-113 states the seed rule. The third, usage on wrong arguments, already works in two places: the verdict arm (main.rs:147) and the app (crates/app/src/main.rs:24). The cheap options move that truth to where the agent reads. The expensive ones make the next drift fail a test, or let the harness describe itself.

The blindspot pass already showed how the help work can go wrong: --help taken as a value, help keys that are not usage patterns, and the stop hook reading xtask's JSON layout. Cards below cite it where an option inherits one of those problems.

#3

Make the fallback error name the word it did not recognize

S
xtask/src/main.rs:264

Found in code: Every miss gets the same string, whether it is a made-up command, a missing profile, an extra word or missing flags. The error could name the first word it failed on and, for an unknown first word, list the 17 command words in the help table (agent-stop architecture check complete coordination docs doctor env gaps handoff map readiness release run scenario task-artifact workflow, counted from cargo xtask help).

Against the ticket: The plan's Scope asks the fallback for one thing, "the usage of the commands that start with the same words". It never asks the error to name a word or list commands, so this card goes beyond the ticket. It must still pass the acceptance line for an unknown first word: "the error points at cargo xtask help and lists no usage". I take "usage" to mean a help entry's argument pattern, such as complete --task ID --base REV --report PATH. On that reading a bare list of command words is not usage, so the test needs no change.

#4

#5

Per-command --help and help WORDS, read from one table

M
xtask/src/main.rs:79-102

Found in code: The help table is a json! literal inside the [] | ["help"] arm, so neither a --help flag nor the fallback can read it. The fix moves it into a function that both call and reads --help or -h before the match, stopping at the first --. Without that, check, workflow and release bind the flag as a value, and run -- --help must stay the app's (blindspot card 01). Today both spellings of the agent's question fail.

#7

Tests that tie the docs and help text to the code they describe

M
xtask/src/transitions.rs:245 · scripts/agent-hook.sh:13 · xtask/tests/hooks_stop.rs:66

Found in code: The repository does this once already. agent-hook.sh:13 says its lists are "Copied from xtask/src/transitions.rs; transitions::tests keeps them equal". Nothing ties ARTIFACTS.md Task size to SEEDS or CEREMONY_SKILLS, or the help text to the hook configs, which hooks_stop.rs:66 already parses. Two tests would close both gaps. One checks that Task size names every SEEDS folder and seed path. The other checks that every xtask command a hook script runs is in help, and that no entry calls itself a hook gate unless a hook runs it. The ticket's agent_stop_help_names_the_hook_that_runs covers only the agent-stop part.

Reasoned, not run: the Task size test would have failed at 331c2ca, since that commit's sentence names no seed.

ImpactThe next time either statement goes wrong, a test fails instead of a fresh agent being misled.

#9

Replace the hand-written match with clap

L
harness/config.json:18-24 · xtask/Cargo.toml · README.md:67 · scripts/agent-complete.sh:78, 87

Found in code: clap would generate --help and usage-on-error for every command. It costs three things. The tooling layer may depend only on serde, serde_json and sha2, and widening that list asks the owner, as captured below. clap prints help as plain text and prints usage errors to stderr with exit 2 (clap's Error::exit docs), but README.md:67 promises JSON on stdout. The stop hook would class an exit-2 reply as "could not run" (agent-complete.sh:87), which is the correct reading of a malformed call.
