02Why ship it

When PR #4 shipped the page loop, its review of the buy-in doc found a misdirection. While reviews.json had any uncommitted row, next told the agent to commit the first passed page in table order (router.rs:236 at the plan commit), which case 1 reproduces. The rows also could not say how often a page type or a reviewer model forces a rewrite, because they held neither a count nor a model. The investigate brief that GEPA optimises was a file that neither host loaded, and no check read it.

After this change the agent gets the right step. New rows can be counted by page type and model: this branch's review of its implementation notes is the first, with "findings": 3, "model": "sonnet". The brief is usable as a skill and cannot drift from the GEPA seed. Nothing gates: next still only advises, and complete and handoff still never read the log. No CI workflow changed; the docs step that check ci runs gains DOC009 and DOC010.

05Known limits, and what you decide

  • Compatibility runs one way. Rows keep deny_unknown_fields (router.rs:29), so an xtask built before this change refuses a log holding a counted row. Run in the case 1 clone: unknown field `findings`, expected one of `page`, `round`, `verdict`, `sha256`, `reviewer`, `notes` at line 83 column 16, exit 1, for both next and verdict. A branch cut before this change must rebase before it records a review on such a log.
  • --model's limit of 64 counts bytes. The check is model.len() > 64 (router.rs:130). 32 × é (64 bytes) is accepted, and 33 is refused with "must be at most 64 characters". Hosts name their models in ASCII, where bytes and characters agree.
  • DOC010 looks only for ": ". The check is v.contains(": ") (checks.rs:232), so a description ending in a bare colon slips past it. With both investigate copies set to description: Investigate this repository before changing it. Use it when:, cargo xtask docs in a clean clone of the branch tip reports no errors and exits 0, while yaml.safe_load on the same frontmatter raises mapping values are not allowed here. Quoting the description, as both shipped skills now do, avoids it.
  • The evaluator may show the seed to every candidate. snapshot() writes every file of the task commit's git archive into each trial (experiments/evaluator/workspace.py:14-32; from the plan, lines re-read, the evaluator not run). If a suite's task repositories are made from this template, the investigate skill, which carries the seed's text, sits beside every candidate. The bundled demo's repository has no skills (demo.py:22-30). Real suites are unchecked. A fix would belong in the evaluator.
