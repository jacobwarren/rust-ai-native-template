A1 · Data model: two optional fields on the review row

// xtask/src/router.rs:28-45, unchanged fields condensed
#[serde(deny_unknown_fields)]
pub struct Row {
    // page, round, verdict, sha256, reviewer, notes
    #[serde(default, skip_serializing_if = "Option::is_none")] ①
    pub findings: Option<u32>,     ②
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub model: Option<String>,     ③
}   // Log { schema_version: 1, rows } unchanged
  • ①An absent field stays absent on write, so a verdict appends its row and leaves every earlier row byte-identical. On HEAD's seven-row log plus the row below, git diff --numstat reads 10 0. Plain #[serde(default)] would write null into each old row (blindspot 02).
  • ②Every finding the reviewer listed, blocking or not, so a PASS with open notes still has a count. A missing field means "not recorded", never 0 (interview Q3).
  • ③The reviewer's model as the host names it, such as gpt-5.1. The author's model is not recorded (interview Q4).

This page's own first review, replayed with the new command in a clean copy. The model name is assumed; the review itself recorded none.

{ "page": "plan.html", "round": 1,
  "verdict": "revise", "sha256": "d96dfbda…",
  "reviewer": "artifact-reviewer",
  "notes": "A1 error line/column from an older log …",
  "findings": 3, "model": "claude-opus-5-5" }
Choice ①

Pick: additive optional fields, schema_version 1, old rows untouched.

Alternative: schema_version 2 with old rows backfilled from their notes. Weighed in blindspot 03 and interview Q2.

Limit I'm keeping: compatibility runs one way. Rows stay deny_unknown_fields, so an xtask built before this change refuses a log holding that row: 
$ cargo xtask task-artifact next --task router-polish
{"error":"reviews.json: unknown field `findings`, expected one of `page`, `round`, `verdict`, `sha256`, `reviewer`, `notes` at line 67 column 16","ok":false}
Exit 1, and verdict fails the same way, so a branch cut earlier rebases before recording a review on such a log. complete and handoff don't read it.

A2 · The verdict command and the Review struct

cargo xtask task-artifact verdict --task ID --page PAGE --verdict pass|revise|best \
    --reviewer NAME --model MODEL --findings N --notes TEXT
// xtask/src/router.rs:95-106, fields condensed
/// One review as given on the command line, before it is checked.
pub struct Review<'a> { page, verdict, reviewer, notes,
    findings, model: &'a str }   // each pub &'a str
pub fn verdict(root: &Path, id: &str, review: &Review)
    -> Result<Value>
  • All flags are required, in this order, and best takes them too. A sixteen-element arm in main.rs replaces the twelve-element one; a catch-all arm after it refuses every other verdict shape. The help line and next's review step print the same command.
  • The struct carries raw strings and verdict() checks them; eight positional parameters would trip clippy's too_many_arguments. --model gets its own rule because valid_id refuses the dot in gpt-5.1 (blindspot 04).
What verdict answers, run in the clean copy
--findings two, --findings -1--findings two must count the findings the reviewer listed, echoing the bad value
--model 'gpt 5', --model ''--model names the reviewer's model as the host does, without spaces
--model of 65 characters--model must be at most 64 characters (64 is accepted)
The old six-flag form, or --findings before --modelThe full usage line, ending in that order; --model and --findings are required
--model gpt-5.1 --findings 0Recorded, with "findings": 0, "model": "gpt-5.1"
Choice ②

Pick: both flags required on every verdict, in one fixed order.

Alternative: optional flags, one match arm per combination. Weighed in blindspot 04 and interview Q5.

A3 · What next says: the commit step belongs to the page reviewed

// next(), router.rs:314-320: rows HEAD holds
let committed_rows = match (&log, history::read(root, "HEAD", &log_path(id))?) {
    (Some(log), Some(bytes)) => parse(&bytes).ok()
        .filter(|c| log.rows.starts_with(&c.rows))
        .map_or(0, |c| c.rows.len()),
    _ => 0,
};
// page_step(), router.rs:273-276
let pending = log.is_some_and(|l| l.rows.iter()
    .skip(committed_rows).any(|r| r.page == page));
if committed && !pending { return Ok(None); } // done
  • The log only grows, so rows past HEAD's row count are the uncommitted ones. A page waits only for its own.
  • The page-file check stays: a page edited after its committed pass still gets a commit step.
  • If the working log doesn't start with HEAD's rows, committed_rows is 0, every page with rows waits, and the existing advisory says why.
