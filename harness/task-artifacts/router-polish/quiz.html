1 · Context

After workflow-router merged, the owner asked for three fixes. While reviews.json had an uncommitted row, next told the agent to commit the first passed page in table order rather than the page just reviewed; the brainstorm found the same wrong answer in the middle of a rewrite. Rows had no finding count and no reviewer model, so rewrite rates per model could not be computed. And docs/skills/investigate.md, the seed GEPA optimises, was not a skill either host could load, and no check read it.

The owner delegated the calls. The interview settled the flag order and the rule for pending rows, the plan tabulates what verdict refuses and what next says, and the implementation notes record the YAML gap the build found. None of that is repeated here.

2 · The mental model

The log only grows. Whatever the last commit holds is a prefix of it, so the rows after that prefix are the uncommitted ones, and each belongs to one page. 3 · Intuition: five behaviours a diff skim misses

01A page waits only for its own rows after HEAD's last row

xtask/src/router.rs: next 314-320, page_step 273-276, condensed
committed_rows = HEAD's log is a prefix of the working log ? its row count : 0
pending        = any row after committed_rows has page == this page
done           = page file clean in git status && !pending      // else: commit
Position
Which rows are pending depends on where they sit, not on what they say. The interview showed why a content match fails: a row can repeat an earlier one exactly.
Rewritten
If a committed row was changed by hand, the prefix test fails, committed_rows is 0 and every page with rows waits, beside the existing advisory "no longer starts with its committed rows".
Unchanged
verdict refuses pass or revise only when the page's last row has the page's current hash (router.rs:159). A pass row's round is the page's revise count plus one.

02Two optional fields, written only when present, read by a strict parser

Shape
findings: Option<u32> and model: Option<String>, each #[serde(default, skip_serializing_if = "Option::is_none")] (router.rs:39-44). A row without them reads as absent, and writing the log back leaves it without them; a new verdict adds ten lines and changes none. Nothing backfills; schema_version stays 1.
Strict
Row and Log keep deny_unknown_fields (router.rs:29, 48). Each task has its own reviews.json, and next and verdict parse the whole of it. The plan (A1) shows what an xtask built before the fields prints on such a log.
Meaning
findings counts every finding the reviewer listed, blocking or not, so a pass with open notes has a count. model is the reviewer's model as the host names it, dots allowed. The author's model is not recorded.

03verdict has one argument shape, checked before anything is read

xtask/src/main.rs:88-120, then router.rs: verdict 106-169, condensed
[.. "--task",id,"--page",p,"--verdict",v,"--reviewer",r,
    "--model",m,"--findings",n,"--notes",t]  → router::verdict(..)
["task-artifact","verdict", ..]              → usage error, nothing read or written

verdict: page is a task page → verdict word → reviewer id
       → n.parse::<u32>()          // digits, one optional leading +; stored as a number
       → model: non-empty, no whitespace, ≤ 64 bytes
       → page file exists
       → pass|revise: refuse this exact version again; refuse after 3 revises
         best: round = the reviewed row whose hash equals the page
best
Is matched by the same arm as pass and revise, so it takes all seven flags; the guide's verdict line and next's review step print the same command.

04DOC009 reads one skill copy; DOC007 holds the other to it

Seed
docs/skills/investigate.md is unchanged and stays the seed GEPA pastes whole into the agent's prompt. Both SKILL.md copies are frontmatter followed by its bytes.
DOC009
Takes the .claude/skills copy only, strips ---\n…\n---\n and leading newlines, and compares the rest with the seed's bytes (checks.rs:240-255, SEEDS at 260).
DOC007
Already required every file under the two host skill folders to be identical (checks.rs:201-208).
Rule
experiments/gepa/README.md now says to copy an approved improvement into both skill files; the README names DOC009.

05DOC010 refuses an unquoted ": " in a skill's description

Rule
For every SKILL.md in each host folder, a frontmatter line description: whose trimmed value does not start with ", ', > or | and contains a colon followed by a space is reported, once per file (checks.rs:225-236).
Why
Strict YAML reads a: b inside a plain value as a nested mapping. Codex's skill validator parses with yaml.safe_load (implementation notes, gap 1).
Fix
The investigate and add-product-command descriptions are double-quoted on both hosts.
