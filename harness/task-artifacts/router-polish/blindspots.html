The blindspots

Landmine01

next sees only whole files, and the obvious per-row fix keys on a hash two rows share

page_step calls a page done only when the page file and the entire log are clean in git status (router.rs:189-192, 236-238). next walks pages in table order (277-306), so while any row is uncommitted, the first passed page gets the commit step. That is the ticket's bug.

The fix asks whether this page's last row is in HEAD's log, which next() already reads for the advisory (269-270). The key is the trap. A best row takes the hash of the version it restores (125-130), so it shares sha256 with an earlier revise row. Round 1 committed as revise, two rewrites reviewed, round 1 restored as best:

HEAD     {"page":"blindspots.html","round":1,"verdict":"revise","sha256":"13e45918…"}
working  {"page":"blindspots.html","round":1,"verdict":"best",  "sha256":"13e45918…"}
$ git status --porcelain
 M harness/task-artifacts/TASK-1/reviews.json   # the page itself is clean: it is round 1 again

Row derives PartialEq (28-39), so whole-row equality is free. Keep the page check too: tests/router.rs:84-101 pins a page hand-edited after its committed pass as a commit step.

Why it bitesA lookup by page and hash finds the committed revise row and moves on, leaving both revise rows and the best row uncommitted. The ticket's test never reaches this path.
Landmine02

An Option field keeps old logs parsing, but the next verdict rewrites every committed row

Row and Log are deny_unknown_fields, and parse() accepts only schema_version 1 (router.rs:28-58). verdict() reads the whole log, pushes one row and writes the whole log back (108-111, 158-162). In a scratch copy I added findings: Option<u32> to Row, before or after notes, and recorded one verdict on workflow-router's 11 committed rows:

# #[serde(default)]
"findings": null  × 12     # each of the 11 old rows gains the key, plus the new row
# #[serde(default, skip_serializing_if = "Option::is_none")]
"findings": null  × 0      # old rows unchanged; the diff is the new row only
# schema_version required to be 2
$ xtask task-artifact next --task workflow-router
{"error":"reviews.json: schema_version must be …","ok":false}   exit 1
Why it bitesThe ticket's "old rows still parse" test passes with plain #[serde(default)], and the "no longer starts with its committed rows" advisory (269-275) stays silent because null parses back to None. The only trace is a diff that edits every row of an append-only log.
History03

The 11 committed rows keep their counts as prose, and filling them in edits history

workflow-router's reviews.json is the only log. Its rows name the subagent artifact-reviewer, not a model, and keep open items in the notes ("Open: …"). Setting findings: 2 on one by hand makes next warn that the log "no longer starts with its committed rows" (router.rs:269-275).

Convention04

main.rs matches argv as one exact, ordered slice; an optional flag means another arm

dispatch() matches the whole argument list as a slice (main.rs:51-56). verdict is one twelve-element pattern (88-101), and optional arguments elsewhere are extra arms: handoff, gaps and readiness each appear with and without --report (121-124, 175-182). In the clean copy:

$ xtask task-artifact verdict --task … --page … --verdict … --reviewer r --notes n --findings 2
{"error":"unknown command or extra arguments; run cargo xtask help","ok":false}
$ xtask task-artifact verdict --task … --reviewer r --page … --verdict … --notes n
{"error":"unknown command or extra arguments; run cargo xtask help","ok":false}
$ xtask task-artifact verdict … --reviewer gpt-5.1 …
{"error":"--reviewer names who reviewed, in letters, digits, - and _","ok":false}

Two optional flags make four order-strict arms, and the refusal names no flag. Agents copy the command from the help (main.rs:74), the say text next prints (router.rs:199) and ARTIFACTS.md:51-52. valid_id (config.rs:123-129) refuses dots, so reusing it for --model rejects gpt-5.1.

Why it bitesIf the flags are optional and line 199 doesn't carry them, no row ever gets a count or a model.
Missing concept05

No file records the reviewer's model, and it can't explain an author's rewrites

.claude/agents/artifact-reviewer.md:4 says model: sonnet, an alias that a per-invocation model parameter overrides (Claude Code subagent docs). .codex/agents/artifact-reviewer.toml names no model, so the Codex reviewer inherits the parent's unless the spawn or an [agents] default sets one. The reviewer has no Write or Edit tool (artifact-reviewer.md:5), so --model is the orchestrator's account of what it started.

Why it bitesThe ticket wants "rewrite rates per page type and per model", but a rewrite means the author's page failed, and no row carries the author's model. Copying "sonnet" from the frontmatter is wrong whenever the orchestrator passed a model.
Landmine06

The seed is pasted whole into the agent's prompt, and no check or CI job reads it

The agent-workflow buy-in kept investigate.md a plain doc because it is the experiments' seed. experiments/README.md:37 passes it as --candidate, trial.py:62-63 checks only its size, stdin_agent.py:14-17 pastes it into the agent's prompt, and GEPA optimizes seed_skill as one text (gepa/config.py:47-49, optimize.py:70-76). With a SKILL.md as the candidate:

$ python3 experiments/evaluator/stdin_agent.py -- cat < request.json   # candidate = frontmatter + seed
Use this investigation skill, subject to repository rules:
---
name: investigate
description: Investigate this repository before changing behavior.
---
# Repository investigation skill …

No check reads the seed. The experiment-contracts job (ci.yml:54-87) uses its own (test_gepa.py:45, demo.py:58), DOC007 compares the host folders only with each other, and DOC008 reads only name: (checks.rs:189-228). With both copies one sentence off the seed, cargo xtask docs reported no skill error. A "moved" note like docs/skills/author-artifact.md, PR #3's precedent, would become the candidate and pass every check. Each new SKILL.md also needs its own harness/docs.json entry, or DOC004 fires (checks.rs:153-162).

Why it bitesThe skill and the seed drift apart silently. The first sign would be a paid GEPA run that optimized the wrong text.
