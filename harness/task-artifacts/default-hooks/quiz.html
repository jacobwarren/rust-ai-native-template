Default hooks: what changed, and a quiz before you merge

I want to make sure I understand everything that happened in this change before I merge. Give me an HTML report on the diff, covering context, intuition and what was done, with a quiz at the bottom that I must pass.

Claude Code and Codex now run three hooks by default: a guard before each edit and shell command, a compile check after each edit, and a stop gate that judges only claims of completion. Mostly this moves CI's checks to the moment the agent acts; four rules are new (Context).

01Context: the rules were text until the PR

Before, on main

  • Goldens, new dependencies and merging were sentences in AGENTS.md. CI's check ci and, on PRs, handoff were the first code to act on them.
  • The only hooks were an opt-in Codex example. Its guard saw apply_patch only, and its stop hook blocked every stop unless two environment variables were set.
  • No Claude Code configuration at all.

After, on this branch

  • .claude/settings.json and .codex/hooks.json wire scripts/agent-hook.sh (new: guard, check) and scripts/agent-complete.sh (rewritten). The Codex example keeps only its discovery-page guard.
  • New rules: (1) .claude/ and .codex/ are protected, so weakening a hook needs a transition receipt; (2) Codex refuses edits to goldens and harness/config.json where Claude Code asks; (3) a PR merge asks on Claude Code and is refused on Codex, and a force-push is refused on both; (4) cargo add and cargo remove ask first.

02Intuition: cheap and unbreakable first, compile later, CI last

The first checkpoint runs on every call and must work while the code is broken, so it only reads text. Later ones can afford Cargo. CI keeps the final say: no local setting reaches it.

Before a tool call

guard

Edits, patches and Bash. Sorts each path the call writes into a tier. Can block.

After an edit

check

Edit tools only. Compiles and lints what changed, then runs the architecture check. Reports; can't undo.

At stop

stop gate

Runs the completion gate only when a record claims complete. A refusal keeps the agent working.

At the PR

CI

check ci and handoff judge everything else: partial records, stray files, receipts. Hooks never run here.

03What was done, one run each

01One decision, two host dialects

decide picks the strictest tier among the call's paths. ask answers Claude Code in its JSON. Codex parses ask but marks the hook run failed and lets the call proceed, so on Codex the same function exits 2. Paths become repository-relative against the event's cwd, and a .. is resolved on the string, not refused (relative, normalize).

guard claude → {"hookSpecificOutput":{"permissionDecision":"ask","permissionDecisionReason":"harness/goldens/replayed.json is a golden baseline. …"}}  exit 0
guard codex  → Blocked: harness/goldens/replayed.json is a golden baseline and Codex hooks cannot ask. …  exit 2

02Shell commands are judged by where they write

shell_targets reads the command as text and never runs or expands any of it. Quoted strings and heredoc bodies stay single words. It keeps only destinations: redirect targets, the last operand of cp or install, operands of mv rm tee truncate, files of sed -i, and paths after git checkout or restore. Each destination takes the tier an edit to it would.

# Codex, Bash
git commit -qm "bless harness/goldens/lifecycle.json" && sed -i.bak s/old/new/ harness/config.json
  → Blocked: harness/config.json holds the dependency allowlists and Codex hooks cannot ask. …  exit 2
cat harness/goldens/lifecycle.json > /tmp/l.json; git diff --stat harness/goldens
  → {}  exit 0

03After an edit: compile what changed, then run the built xtask

A .rs edit runs cargo check --locked --all-targets and cargo fmt --check on the nearest package. An edit to any Cargo.toml, Cargo.lock or harness/config.json checks the whole workspace. Both then run target/debug/xtask architecture, which checks the dependency layers and every .rs file's length. It runs the binary because the cargo xtask alias passes --locked, so Cargo stops it before xtask starts once a manifest names a crate the lock lacks. Docs edits run nothing. A failure exits 2: Claude reads the report, and the edit stays written.

# Edit appends  pub fn answer() -> u8 { "42" }  to crates/engine/src/lib.rs
Post-edit check failed. Fix these before continuing:

$ cargo fmt --check -p starter-engine  (exit 1)
Diff in ./crates/engine/src/lib.rs:119: …                                         exit 2

04The stop gate judges claims, never ordinary turns

It collects every task id whose record or artifact folder differs from the merge base, untracked files included, and greps each record for a complete status. It runs cargo xtask complete for those alone. A refusal, or a gate that can't run, exits 2 and sends the agent back to work. Any other stop exits 0 without Cargo. Setting the record back to partial with its remaining actions always clears the block.

ids=$({ git diff --name-only "$base" -- harness/tasks harness/task-artifacts
        git ls-files -o --exclude-standard -- harness/tasks harness/task-artifacts; } | sed … | sort -u)
CLAIM='"status"[[:space:]]*:[[:space:]]*"complete"'   # task_record test keeps this equal to the Rust parser

05Failing closed: the script's part and the host's part

Inside the script, an ERR trap turns a failed command into exit 2. set -u aborts on an unset variable without that trap, so an EXIT trap rewrites every other exit code to 2 as well. A guard that can't start, or runs past its 10 s timeout, is the host's call: Claude Code blocks it with onFailure: "block" from v2.1.295; older Claude Code and Codex let the call through. The stop gate keeps its ERR trap but not -E: under macOS /bin/bash 3.2, -E runs that trap inside a guarded $(…) and misreports a refused claim.

set -uEf
trap '… exit 2' ERR
trap 'rc=$?; case $rc in 0 | 2) ;; *) echo "agent-hook: internal error (exit $rc). …" >&2; exit 2 ;; esac' EXIT

06The tree: hook config is policy, per-machine files are not source

.claude/ and .codex/ join the protected list, now two constants in transitions.rs that the guard copies; guard_tiers_match_protected_paths fails if the copies drift. repo::files walks the disk without reading .gitignore, so on main a "don't ask again" click wrote .claude/settings.local.json and staled CI evidence. HOST_LOCAL now skips that file and .claude/worktrees, by exact root path only.

transitions::protected · repo::files · tests host_local_files_do_not_change_the_tree, committed_local_settings_are_still_reported

Existing behaviour this leans on. Partial handoffs, stray files and stale receipts are still seen only by cargo xtask handoff in PR CI, and only hosting rules can stop a merge. Codex runs none of these hooks until its project .codex/ layer is trusted and each hook is reviewed in /hooks. On Claude Code, "disableAllHooks": true in .claude/settings.local.json turns them off (COMPLETION.md, "Default hooks and CI").
