Eight places to make the rules run instead of being read

The prompt
Here's the problem: the template's rules on goldens, protected policy files, dependencies, merging and completion are instructions an agent can ignore until CI fails, and the only hooks are an opt-in Codex example that blocks every stop when unconfigured. Search the codebase and brainstorm the places we could intervene, from cheapest to most ambitious. I'll tell you which ones resonate.

From xtask/src, scripts/, CI and both hosts' docs; commands ran in a clean clone. "(03)" cites that card of the blindspot pass.

The pattern

Most of these rules already have an enforcer in xtask that runs last, in CI: new dependencies fail ARCH004 unless the protected allowlist in harness/config.json changes (checks.rs:68–69), policy files need a receipt (transitions.rs:37), and handoff has a "nothing changed" path (completion.rs:160). The cheap rungs move those checks to edit time. Only goldens written by a script, which no hook sees (03), and merging, which happens on the host, need something new.

Found in code: Neither directory is protected (blindspot 02), so a later PR can delete the hooks with no receipt. harness/goldens/ (3 files) · xtask/src/golden.rs:27–42

Found in code: Nothing in the harness writes a baseline: golden::compare writes its candidate under target/ and stops. After chmod -R a-w harness/goldens, every write from blindspot 03 failed, including the Python one no hook or rule saw. Renaming the directory did not:

False positivesGit can't update the goldens either: checkouts, rebases and pulls that touch them fail until chmod -R u+w.

#5

Post-edit feedback that also flags new dependencies

S–M

PostToolUse · xtask/src/checks.rs:68–69 (ARCH004) · xtask/src/repo.rs:88 · harness/config.json "layers"

Found in code: The owner's post-edit cargo check must pass --locked or it rewrites the protected Cargo.lock (04). architecture already checks each external crate against its layer's allowlist. With sha2 added to crates/app:

$ cargo check -q --locked -p starter-app
error: cannot update the lock file …/Cargo.lock because --locked was passed   exit 101
$ target/debug/xtask architecture                        # 0.03 s prebuilt
"ARCH004 starter-app -> sha2: external dependency not allowed for this layer;
 justify it in an ADR and update the allowlist."                              exit 1
CatchesCompile errors, formatting and new crates within a second (warm, after a one-line edit: 0.06–0.13 s), on both hosts.
MissesBash writes, cargo add included, which don't fire PostToolUse on Edit|Write. It can't undo an edit. An allowed crate passes, by design.
CostA path-to-package script calling #3's binary, not cargo xtask. Use cargo fmt --check: how Claude reacts to a formatter rewriting its file is undocumented.

A pre-edit guard: shell first, xtask later

M–L

new scripts/agent-guard.sh · xtask/src/artifact_hook.rs:8–32 · transitions::protected

Found in code: Blindspot 05's first option. A dependency-free script greps the event (Claude's file_path, Codex's apply_patch text or a Bash command) for harness/goldens/ and the protected names. It answers Claude with "ask" and Codex with exit 2, since Codex treats ask as a failed hook and proceeds4. Never calling Cargo makes onFailure: "block" safe. Later, xtask agent-hook can reuse artifact_hook::run's apply_patch parsing and CI's own protected().

CatchesEdit, Write and apply_patch to goldens and policy files, and Bash commands naming a golden, on both hosts.
MissesScripts that build the path (03's Python) and MCP writers. The shell copy of protected() drifts; the xtask one needs #3's binary (05).
Cost and false positivesShell: grep, since jq isn't on every Linux. xtask: a module, tests, a policy receipt. Both: cat or git diff on a golden needs an allowlist.

Put the authority outside the repository

L–XL

.github/workflows/ci.yml · harness/gaps.json hosting-enforcement · docs/COMPLETION.md:172–175 · .claude/settings.json "sandbox"

Hosting rules

Found in code: CI can't supply authority: the agent that copied the golden writes the receipt (03), and "local hooks and self-authored receipts cannot enforce that authority" (COMPLETION.md:174). CI runs after a push, so it can't stop a force-push or a merge. A ruleset can: required checks, CODEOWNERS on goldens, xtask/, .claude/ and .codex/, owner approval to merge. That closes gap hosting-enforcement, which no file here can configure.

Claude's Bash sandbox (documented, not tested)

sandbox.filesystem.denyWrite is OS-enforced for sandboxed commands and their children6; Codex documents no per-path write deny7.

CatchesHosting: merges and force-pushes, with real authority. Sandbox: script writes to goldens on Claude.
MissesHosting: everything during the session. Sandbox: Codex, and Windows outside WSL2.
CostHosting: per-adopter settings, documented because they can't ship. Sandbox: untried whether Cargo's ~/.cargo writes and fetches work in it.
