Default hooks for Claude Code and Codex are ready to ship

The prompt

Package the plan, the implementation notes and the evidence into a single doc I can share to get buy-in on shipping default project hooks for Claude Code and Codex in this template. Lead with the demo.

Agents in this template are told never to regenerate golden test baselines, to ask before adding a dependency, and never to force-push or merge without the owner. Until now only CI enforced that, after the fact. This change ships project hooks for Claude Code and Codex that apply the same rules as the agent acts: a guard before each edit and shell command, a compile check after each edit, and a gate when the agent stops. No new policy; CI is unchanged.

Ships .claude/settings.json, .codex/hooks.json, .codex/rules/default.rules, a new scripts/agent-hook.sh and a rewritten scripts/agent-complete.sh. The repository owner asked for it and settled the design in chat, including the two behaviours added during the build (04).

03What it does not do

Failing closed depends on the host

An error inside the guard script exits 2 and blocks on both hosts. A guard that cannot start (exit 127 outside a checkout) or runs past its 10 s timeout blocks only on Claude Code v2.1.295+ (onFailure: "block"); older versions and Codex let that call through, and no setting can require the version (docs/COMPLETION.md). Codex runs nothing until .codex/ is trusted and each hook reviewed.

Rules and the parser are speed bumps

Command rules match literal prefixes, so git -C . push --force and +main match none; the guard catches them (case 3). A script that builds the path (case 11), cd harness && mv goldens old, and sh -c or eval strings pass the guard. Shell writes to .rs files get no post-edit check.

The stop gate does not give up by itself

agent-complete.sh ignores stop_hook_active on purpose: passing a repeated false claim would mean not gating it. Its refusal tells the agent to set the record back to partial, which always clears the block (case 10). Failing that, Claude Code ends the turn after 8 consecutive continuations (CLAUDE_CODE_STOP_HOOK_BLOCK_CAP; the count resets whenever the agent calls a tool). Codex's hooks page names no cap; the user can interrupt.

Hooks never run in CI, and cannot replace hosting rules

CI still runs cargo xtask check ci and, on pull requests, handoff (.github/workflows/ci.yml:33, :41); stray files and missing receipts surface only there. The guard asks before or refuses the agent's merge commands; it does not stop an agent with the owner's credentials merging another way. Each adopter still sets branch rules (open hosting-enforcement gap, harness/gaps.json).

Most host reactions come from docs

Seen live in the Claude Code session that built this change: the policy-file note reaching the agent (case 6) and the stop gate ending each turn silently (case 9). Not seen live: Claude Code's ask and deny prompts, how it shows a post-edit or stop exit 2, and any hook inside a Codex session. Codex's rules were checked offline with codex execpolicy check (case 5), never loaded in a session. An edit whose paths the guard cannot read is refused, since Codex's patch format and Claude Code's MultiEdit input are undocumented. .. is resolved first: crates/../harness/goldens/kept.json is a golden; a write outside the checkout passes.

04Decisions

The owner answered the design questions in chat on 4 November 2026. Rows 3 and 5 were changed during the build, stricter than the first answers; the owner approved both after reviewing the PR.

DecisionAs builtStatus
1. When stopping is blockedOnly when a task record changed on the branch says "status": "complete" and the existing gate (cargo xtask complete) rejects it. Partial handoffs are left to PR CI.owner decided
2. The guardBash and awk, never Cargo; a test keeps its path lists equal to xtask/src/transitions.rs. Goldens and harness/config.json: Claude Code asks, Codex refuses. Other protected files, now including .claude/ and .codex/, get a receipt note. Shell commands are judged by where they write, not what they mention (case 2).owner decided
3. Shell writes get the edit tiersThe plan tiered only shell writes to goldens, so sed -i could widen the allowlist unasked: the Edit(/harness/config.json) ask rule never sees shell commands. Now each shell write gets the tier an edit would (case 4), notes included.owner approved
4. After an editcargo check --locked and cargo fmt --check on the edited crate, then xtask architecture (cases 7, 8). A narrowing to manifest edits only was approved on a false premise (its 400-line check reads every .rs file, xtask/src/checks.rs:76–90) and dropped.owner decided
5. The check compiles tests too--all-targets: a plain cargo check never compiles crates/*/tests/, so errors there would go unreported.owner approved
6. Dependencies and mergingAsk before cargo add|remove. A PR merge (gh pr merge, the merge API) asks on Claude Code and is refused on Codex; every force-push spelling is refused on both; local git merge is allowed.owner decided

Two build fixes restore what the plan said: the fail-closed error trap reaches every function, and a check that cannot rebuild xtask says its result may be stale.
