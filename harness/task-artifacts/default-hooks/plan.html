A3 · The stop gate: the shell finds the claim, existing xtask judges it

Your Q1 ("new xtask mode") and reference D1 ("found without xtask") answer one question: does a record changed on this branch claim complete? After a turn adds a crate, cargo xtask exits 101 before xtask runs (the alias passes --locked, .cargo/config.toml:2), so D1's shell search has to exist anyway. The choice is one detector in shell or two plus a parity test; speed doesn't decide it.

What runs at every Stop

Plan's pick: claim search in agent-complete.sh, judged by the existing cargo xtask complete

Root from the event's cwd. Base = git merge-base HEAD ${HARNESS_BASE:-origin/main}. No base: exit 0 with a warning.
Changed ids: git diff --name-only BASE plus git ls-files -o --exclude-standard over harness/tasks/ and harness/task-artifacts/
For each id, grep only harness/tasks/ID.json for "status"[[:space:]]*:[[:space:]]*"complete". None: exit 0 without running Cargo.
Claim: cargo xtask complete --task ID --base BASE --report …. Exit 0: stop. Pretty JSON with exit 1: refused, exit 2. One-line {"error", 101 or other: gate broken, exit 2.

Observed: with rand added to crates/app/Cargo.toml, cargo xtask agent-stop exited 101 ("cannot update the lock file"). Prebuilt and warm, the search takes 0.06 s and a claims-only Rust mode about 0.3 s; a claiming turn runs complete either way, and completion.rs stays untouched.

Given up: the record search in Rust beside handoff, and the remaining list, which neither host shows on exit 0. A test in B keeps the grep in step with task_record::read.

Alternative: your Q1 as written, a new agent-stop --claims mode

Extract changed_records() from handoff (completion.rs:134–145)
Run complete() for each record marked complete
Otherwise return {"ok":true,"kind":"stop","remaining":[…]}
The shell keeps D1's grep for exit 101 or {"error", so there are two detectors and a parity test

Pick this if you want the record search in Rust beside handoff, where it shares changed_records(). It costs a new mode and its tests, a parity test against the shell fallback, a receipt line for completion.rs, and about 0.3 s of Cargo start-up per turn.

It ignores stop_hook_active: setting the record back to partial always clears a block, and the refusal says so. Gating a false claim once would mean not gating it.

Narrower than today's opt-in script. Today it blocks every stop until HARNESS_TASK_ID and HARNESS_BASE are set, then runs agent-stop, which checks handoff and the policy receipt even when nothing is claimed (completion.rs:237–247). As your Q1 chose, a turn that claims nothing now just stops, and those failures surface at PR CI (ci.yml:41). Users who exported the variables keep their base and report path; their HARNESS_TASK_ID still drives the opt-in discovery guard but no longer picks the task here.

D

Mechanical work

low tweak likelihood
Plumbing with no judgment calls · 6 items, each with a trap
  • Read event fields with POSIX sed and awk, no jq. Split the patch's escaped \n before matching the four prefixes anchored at line start (reference pair C, note 10).
  • Use set -u and trap 'echo "agent-hook: internal error, line $LINENO" >&2; exit 2' ERR, never bare set -e.
  • Strip the root in the event's own spelling and in git rev-parse --show-toplevel's, since /var/… and /private/var/… both occur (pair C, note 11). Paths outside the root pass, and .. is blocked.
  • Match harness/goldens with and without its trailing slash (pair D, note 14).
  • From commit 2 on, the guard runs on this session's own calls. Edits to scripts/, xtask/ and docs get notes, and commits naming goldens are mentions, but a crash blocks every Edit, Write and Bash (onFailure: "block" and the ERR trap), including the fix. Pass bash -n and the guard tests with the script alone, write the settings entry last, and if the session locks anyway, restart with claude --settings '{"disableAllHooks": true}'.
  • Split Bash commands on ; && || | only outside quotes, and drop heredoc bodies first, or fixture text in a test file reads as a golden write (A4).
