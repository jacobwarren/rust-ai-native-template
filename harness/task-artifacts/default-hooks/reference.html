Semantics map: the opt-in hooks and the PR gate, ported to default hooks

The prompt
The existing opt-in hooks (examples/codex-artifact-hooks.json, scripts/agent-artifact-write.sh with xtask/src/artifact_hook.rs, scripts/agent-complete.sh with completion::agent_stop) and the PR CI gate (completion::handoff and transitions::check) already behave the way the default hooks should: classify a tool event's paths, decide on the repository's own policy tables, and refuse a false completion. Read them and show me a semantics map, with matched excerpts, gotchas and edge cases, so I can confirm you understood it before you build anything.

Each part of the design you chose in the interview, set beside the code it reuses or copies. Left columns are real excerpts. Right columns are sketches of the new code, written to show the mapping, not to be merged. Every behaviour marked observed was run in a clean clone of this branch.

What the reference actually does

  • Classification is by repository-relative path. artifact_hook::run takes paths from four line prefixes of a Codex patch; artifacts::relative rejects paths outside the canonical root and any . or .. component; no path at all is an error, not an allow.
  • The policy table is one private function. transitions::protected (transitions.rs:37–61): five prefixes and eleven exact names, called only on file paths from the tree walk (:111–112). It means "needs a receipt", not "never edit" (blindspot 02).

/// Stop: refuse only a false completion claim.
pub fn agent_stop_claims(root: &Path, revision: &str,
                         report: &Path) -> Result<Value> {
    let base = history::merge_base(root, revision)?;
    let before = history::before(root, &base)?;
    let after = history::current(root)?;
    let mut remaining = Vec::new();
    for id in changed_records(root, &before, &after)?1 {
        let record = task_record::read(root, &id)?;
        if record.status == Status::Complete {
            let gate = complete(root, &id, revision, report)?;
            if gate["ok"] != true { return Ok(gate); }
        }2 else {
            remaining.push(json!({"task": id,
                "remaining": record.remaining}));3
        }
    }
    Ok(json!({"ok": true, "kind": "stop",
        "remaining": remaining}))4
}
1Same record search, extracted. A record counts when its JSON or anything in its artifact folder changed since the merge base. Sharing changed_records() keeps handoff and the stop mode in step, and needs no HARNESS_TASK_ID. A stale base makes it treat already-merged records as this branch's work; the hook won't fetch ("no … network calls", COMPLETION.md:164).
2The claim branch is reused unchanged. complete() (:110–118) also runs transitions::check, so a claim on a branch that edited a protected file still needs its policy receipt. Observed: this record set to complete with no CI report gets seven errors: four review.*, a missing reference.html, CI evidence and requirement completion.
3Deliberately different: no partial path. Both references run task(…, false) on a partial record, which blocks mid-task on empty review.* answers (blindspot 01). The stop mode only collects remaining; whether an allowed stop shows it to the agent depends on the host.
4Deliberately different: no stray-file error and no gap reconciliation. Line 160 fires on any untracked file when no record changed (blindspot 06). Deleted task history, pages without a record and unaccounted gaps (:129–133, :163–198) also stay with handoff, which PR CI still runs (ci.yml:35–41).

An edge case the pairs don't cover

Bash writing to goldens: rm -r harness/goldens, cat x > harness/goldens/a.json, git checkout -- harness/goldens/… new
Today nothing sees these until the receipt at stop or in CI (blindspot 03). The guard matches the directory name without its slash, a redirect makes cat a write, and only git diff|show|log count as read-only git. Scripts that build the path still get through.

Two things to decide, then confirm

D1. When the stop gate can't run

The base doesn't resolve, or cargo xtask won't run (a broken xtask/, or the lock refusal in note 15). Observed: xtask exits 1 with "Needed a single revision" and a failed build exits 101; agent-complete.sh turns both into exit 2 and "Answer the task-review questions". The pre-edit guard depends on neither. A Stop that exits 2 sends the agent back with nothing it can act on. Claude Code's loop cap resets every time the agent runs a tool (blindspot 01).

Finding a claim without xtask: list records as handoff does, with git diff --name-only BASE plus git ls-files -o over harness/tasks/ and harness/task-artifacts/ (observed: git diff alone missed a new record). The two folders play different roles: the grep runs only on harness/tasks/*.json, and a change under harness/task-artifacts/ID/ only puts record ID in the changed set (handoff's prefix check, completion.rs:134–147). Match grep -E '"status"[[:space:]]*:[[:space:]]*"complete"'; observed: a literal "status": "complete" missed "status":"complete", which xtask gated as a claim. Only the top-level field can match, since every record struct denies unknown fields and none nests a status (task_record.rs:16–120). A record that doesn't parse has no such guarantee, so a test must compare the grep with task_record::read on every record and on spacing variants.

D2. A committed copy of a skipped file

The walk skips it, git at the base still lists it, and every later branch looks changed (pair E, note 18).
